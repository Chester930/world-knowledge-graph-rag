## 1. 如何啟用（〔事實〕，讀碼）

1. 在伺服器的環境（`.env` 或行程環境變數）設定 **`TRACE_SEMANTIC_MARKS=1`**（`core/config.py:81` `trace_semantic_marks`，預設 `False`）；重啟 FastAPI（`python -m uvicorn main:app --port 8010`）。
   - ⚠️ 這個旗標同時會讓 trace 的 `semantic_marks`（報告216 起的其他影子標示，如欄位完整度、`lifecycle_state`）也輸出；**全部只記錄，不改回答、排序、截斷、prompt**。
2. 呼叫 `POST /agent/chat`（若有設 `API_KEY`，帶 `X-API-Key` 標頭），例如 JSON：`{"question": "…", "kg_id": "<KG#4 的 id，可省略走全域路由>", "include_retrieval_trace": true}`（`models/document.py:45–76`）。
3. 在 SSE 的 **`event: sources`** 事件裡看：
   - `facts[].document` 與 `triples[].document` 多了 **`effective_status`**、**`effective_pending_dates`**（不需要 `include_retrieval_trace`）；
   - 加上 `include_retrieval_trace=true` 時，`retrieval_trace.facts[]`／`.triples[]` 的 `semantic_marks` 末尾多 **`document_effective_status`**。
4. **不想用時**：把旗標改回 `0`／刪除並重啟，輸出回到與 S2 之前逐位元相同（已由差分測試驗證）。

## 3. 建議觀察什麼（〔判讀〕）

1. **會被提到的待施行法規是否真的出現**：問「進入營繕工程的作業人員要接受什麼訓練」「特別危害健康作業的定義」「教育訓練規則的課程時數」等，看來源是否標出 `has_pending`。
2. **勞動契約法是否被引用**：問「勞動契約是什麼」「勞動契約的約定」，看是否取到勞動契約法並標 `undetermined`（這部法律實際尚未生效，目前 KG#4 當作現行檢索）。
3. **粒度是否太粗（最重要）**：一份 `has_pending` 的文件通常只有少數條文待施行（設施規則 374 條中只有 7 條、1,829 個 Fact 中 105 個）。觀察時請留意：**一個被標成 `has_pending` 的來源，其實際引用的條文是不是待施行的那幾條**。若多半不是，代表文件層標示會**過度警示**，S3 在文件層做事（如附註）會對大量現行有效的事實誤報——這正是需要 S2b（條文層）的證據。
4. `no_information` 的占比與實際使用情境（例如多半是勞基法、職安衛法這類核心法規）：這決定「沒有備註」這個資料缺口值不值得補（見 §5-3）。
5. 回應時間與輸出大小：理論上只增加少量欄位；若有明顯變慢請回報（旗標關閉即回到原樣）。

## 4. S2b 設計草案（條文層標示；〔推論〕，**尚未派工**）

**為什麼需要**：S3（在 prompt 附註「尚未施行」、整條增訂的條文排除）若只有文件層資訊，會把整份文件的所有事實都附註——設施規則 **1,829 個 Fact 中只有 105 個真的待施行**（5.7%），其餘 94% 會被誤報。**S2b 是 S3 的前置條件。**

**目標**：對每筆檢索到的證據（Fact／triple），在 trace 的 `semantic_marks` 多 `article_effective_status`（`in_force`／`pending_whole`／`pending_partial`／`undetermined`／`no_information`，另附 `effective_from`、`locators`），**仍只做影子顯示**。

**做法（不改檢索）**：
1. 只在旗標開啟、且本次證據中**至少一筆屬於 `has_pending` 文件**時才多做事（其餘情況零額外成本）。
2. 在 `chat()` 的 `document_map` 之後，加**一次唯讀查詢**（比照 L3′ 試點的 `ATTRIBUTE_CYPHER` 手法）：`MATCH (f:Fact {kg_id, source_doc_id, source_svo_chunk_index})-[:SUPPORTED_BY]->(a:LawArticle) RETURN source_doc_id, chunk, a.article_no`，取得每筆證據的條號；另對 `has_pending` 文件各取一次已知條號清單（`MATCH (a:LawArticle {kg_id})-[:PART_OF]->(x:Document {source_doc_id}) RETURN a.article_no`；最多 5 份文件、數十至數百筆），供範圍展開（`185-1～185-4`）。
3. 以既有的 `article_effective_status(parsed, article_no, as_of)`（S1 已驗證）計算，結果放進 trace 的 `semantic_marks`。三元組（BFS 邊）用其引用的（文件, 區塊）找同區塊的 Fact 對應條號。
4. 不改 `vector_search_facts`、不改 Fact 結構、不寫資料；新增的查詢是**只讀**且只在旗標開啟時執行。

**風險與限制**：每次檢索多一次小查詢（預估數十毫秒，**未量測**）；僅旗標開啟且涉及待施行文件時發生；`pending_partial` 的項／附表層級仍無法切到 Fact（Fact 以條文為單位）；邊（BFS）無法區分版本的問題（報告266 §6-3）與本任務無關，不處理。

**工作量與分工**：與 S2 相當的離線任務（交 Codex，新增一個唯讀查詢輔助、trace 參數、測試；我用 KG#4 唯讀樣本驗證）。**需要你同意後才寫任務書。**

## 5. 其他待決（〔判讀〕）

1. **S3 政策**（S2b 之後）：整條增訂（`pending_whole`）施行日前排除；修正條文（`pending_partial`）只附註不排除；`undetermined`（勞動契約法）只附註不排除，另請你決定是否要在回答中明講「本法尚未生效」。評測題需另備（凍結題庫只有 `57-CANARY3` 1 題相關）。
2. **`telemetry.py` 的小項**：`"Mapping[str, str] | None"` 註解缺匯入，可在 S2b 順手補。
3. **補資料缺口的選項**：48／64 份文件沒有施行備註（含勞基法）。MOJ 頁面有統一的「部分或全部條文尚未生效，最後生效日期：…」狀態標示（報告270 §1），可評估由 collector 一併蒐集（collector 是你的專案，我不改）。
