## 2. 母體、抽法與不重疊

### 2.1 母體

母體沿用報告200：以空名 Entity（`name=''`）為受詞端點的事實邊之**全部引用**。本次 Cypher 回傳 2,978 條事實邊；解析其 `citations_json` 後得到 **4,764 筆引用**，與報告200 的空受詞 Fact 數一致。

```cypher
MATCH (s:Entity {kg_id: $k})-[r]->(o:Entity {kg_id: $k, name: ''})
WHERE r.citations_json IS NOT NULL
RETURN type(r) AS rel_type, s.name AS subject, o.name AS object, r.citations_json AS citations
```

### 2.2 固定抽法

- 固定種子：`20261001`，與既有 30 筆的種子 `199` 不同。
- 先依 `(文件資料夾名, chunk, 主詞, verb, source_sentence_start, rel_type, source_sentence_end, sample_key)` 排序。
- 為保證不重疊，先排除報告200 既有 30 筆所在的 **30 個文件＋chunk 配對**，再執行 `random.Random(20261001).sample(pool, 70)`。
- 這是比逐筆三元組鍵更保守的排除：同一文件＋chunk 中的其他引用也不抽，因此不會抽到既有 30 筆所在 chunk。排除配對完整清單在 [209_K3空受詞擴大標註_raw.json](209_K3空受詞擴大標註_raw.json) 的 `excluded_chunks`。
- 抽樣結果 70 筆的 `sample_key` 互異；原始抽樣順序另保留 `selection_index`，使用者審閱編號則在疑問筆前置後重新編為 1–70。

## 3. 原句取得方法

沿用報告200 §3：`source_sentence_start/end` 是 chunk 內相對範圍，不是 `original.md` 的全域句子索引。因此每筆先用 `source_doc_id` 對回資料夾，再用 `source_svo_chunk_index` 載入該資料夾的 `svo_index.json` chunk；在該 chunk 的 `original_sentences` 中，以主詞／verb 前六字作子字串比對，若有標點差異則只在定位時去除標點與空白，最後保留原始句文字。每筆再檢查該句是否逐字出現在同一資料夾的 `original.md`。

本次 70／70 筆 `location_status=found`，70／70 筆 `original_sentence_in_original_md=true`。審閱檔把被抽取句標成「chunk 第 N 句」，並保留必要的前句／後句欄位；CSV 同時保留 `source_sentence_start/end`、chunk 內句序與原句。

標註標準沿用報告200 §3：

| 標籤 | 操作型定義 |
| --- | --- |
| `a` | 原句本來沒有受詞，例如狀態／被動／但書／列舉前導語，沒有可獨立成為動作對象的名詞片語 |
| `b` | 原句有受詞，受詞內容被整段併入 `verb`，`object` 留空 |
| `c` | 無法判斷，例如 verb 為空、原句定位與三元組角色不唯一、跨句／列舉錯接或只剩片段 |

每筆的標籤、理由與疑問旗標都是**草稿，未經使用者確認**。疑問標準是：原句與三元組欄位角色不能唯一對應，或無法在 a／b 之間作出有把握的區分；不為了降低比例而硬標。疑問筆 **20／70＝28.6%**，低於報告207 §4 所列過半停止門檻。

## 6. 與報告207 的偏離、限制與不確定處

- 抽樣種子依要求另用 `20261001`；為確保不重疊，實作採整個既有樣本的文件＋chunk 排除，範圍比逐筆鍵更保守，但母體仍是 4,764 筆全部引用。
- 原句定位在比對時增加去標點／空白的輔助層，因部分欄位片語與原句之間有逗號差異；輸出句本身沒有改寫，仍是 `original_sentences` 的逐字內容，並另查 `original.md`。
- 20 筆疑問不是錯誤率，而是執行對話主觀判讀下的「需要使用者看」旗標。使用者可能把其中任何一筆改成另一標籤。
- 本次沒有第二位標註者，不能由這份材料推出 inter-rater agreement。
- 本次工具環境沒有可用的 `ListAgents` 查詢介面，因此 peer 狀態沿用報告208 的防護紀錄；這是本次執行的外部狀態不確定處。
