# RAG 評測管線文獻與專案調整設計

> 建立日期：2026-09-14  
> 目的：將外部評測文獻與本專案現況對照，先凍結評測原則，再修正 RQ1 harness、題目資格、確定性守衛與 lineage 記錄。  
> 本文件不是正式實驗結果；正式數據須待題庫、KG、程式版本與 manifest 凍結後重新產出。

## 1. 執行摘要

本專案的法律 RAG 評測不應由單一 LLM judge 或單一字串分數決定。文獻對 RAG 的共同結論是：檢索品質、context 是否保留證據、生成是否忠實，必須拆開診斷；對長答案則應拆成 atomic claims，而不是用單一二元答案判定。法律場景還需要 source-grounded、可追溯且能識別日期、數字、否定、條件與例外的評測單位。

因此本輪調整採用以下邊界：

1. 原始法規 `exact_span` 是法律真值；KG Fact、模型答案與 judge 只能是系統產物或輔助訊號。
2. `AtomicScorer` 的 exact match 與 deterministic guard 是正式 pass/fail gate。
3. LLM judge 只提供語義診斷，不得把日期、數字、條件或條號的 exact miss 自動升級為通過。
4. 評測正式入口必須排除未核驗題目，並保存排除原因。
5. 每筆結果要同時保存 retrieval、context assembly、generation 與 guard 狀態，避免把檢索失敗誤歸因為生成失敗。

## 2. 文獻對照

### 2.1 RAG 必須分層診斷

[RAGAS](https://arxiv.org/abs/2309.15217) 將 RAG 評估拆成 context relevance、faithfulness 與 answer relevance，指出整體答案分數會混合 retriever、corpus、模型與 prompt 等因素。這支持本專案既有的 `LineageTracker` 三階段設計，但 RAGAS 的 reference-free judge 不應取代本專案的法律原文真值。

[RAGChecker](https://arxiv.org/abs/2408.08067) 更直接提出 retrieval 與 generation 的細粒度診斷指標，並以 human meta-evaluation 比較不同評測指標。對本專案的對應是：保留 `hit_exact_spans`、`retained_exact_spans` 與 generation 缺失診斷，並將錯誤歸因固定在階段邊界，不以最終答案單獨推測根因。

[ALCE](https://arxiv.org/abs/2305.14627) 將 citation recall 與 citation precision 分開，且以 NLI 檢查來源是否支持陳述。這支持把「證據被召回」與「答案陳述被證據支持」分開記錄；本專案的 `exact_span` 與 source locator 比一般 citation 更嚴格，因為法律條文中的日期與義務詞不能只靠語義相似視為等價。

### 2.2 Atomic facts 適合處理部分正確與局部錯誤

[FActScore](https://arxiv.org/abs/2305.14251) 將長答案拆成 atomic facts，再計算各 fact 是否被可靠知識來源支持；論文明確指出二元整體判定會把「部分正確但部分錯誤」的答案壓成同一個結果。

本專案已具備 `AtomicGoldFact` 與 essential fact 概念。調整後採用兩層分數：

- `atomic_accuracy`／`atomic_recall`：描述 fact coverage。
- `is_perfect`：只有所有 essential fact 通過且 deterministic guard 通過才為真。

這能保留部分正確資訊，同時不讓法律關鍵錯誤被平均分數掩蓋。

### 2.3 LLM judge 不是法律真值

[ARES](https://arxiv.org/abs/2311.09476) 顯示可用訓練過的輕量 judge 評估 context relevance、faithfulness 與 answer relevance，並以少量人工標註估計信賴區間。這支持 judge 作為輔助量測，但也表示 judge 本身需要校準與誤差界線，不能無條件視為 oracle。

[Self-Preference Bias in LLM-as-a-Judge](https://arxiv.org/abs/2410.21819) 發現 judge 可能偏好自身或較熟悉風格的輸出；[Judging the Judges](https://arxiv.org/abs/2406.07791) 則指出 LLM judge 存在 position bias。對本專案的直接決策是：

- baseline 生成器與 judge 必須能使用獨立 provider。
- judge 結果要保存，但不能覆寫 exact／guard 結果。
- judge prompt 應輸出 `ENTAILMENT`、`CONTRADICTION`、`UNKNOWN`，格式錯誤或 timeout 必須 fail-closed。
- 法律 critical token 的 exact miss 不可由 judge 單獨補回。

### 2.4 法律評測需要任務與來源層級分離

[LegalBench](https://arxiv.org/abs/2308.11462) 由法律專業者共同建立多種法律推理任務；[LawBench](https://arxiv.org/abs/2309.16289) 將法律能力區分為知識記憶、理解與應用。這支持本專案將 Type-A～Type-E、single／multi-hop、Canary 與 source-grounded exact-span 題目分層統計，而不是把所有題目混成一個總分。

本專案的 `verified` 只代表 gold 已完成原文核驗；它不等於每一題都適合使用同一種 metric。Type-E 應以 correct refusal／false refusal 統計，法律題則以 atomic coverage、critical token、guard 與 source lineage 統計。

| Atomic claim 評估 | `AtomicGoldFact`、字串包含 | 未核驗題目會被空 gold 判成完美 | 加入 eligibility filter 與 guard-aware score |

| 部分正確與拒答 | Type-E、essential facts | Canary 與一般法律題尚未分軌報告 | 每筆標記 track，保留 atomic 與 refusal 指標 |

## 4. 凍結的調整原則

### 4.1 Scorer 原則

本輪不把 LLM judge 直接接成法律 pass gate。先修正最危險的確定性問題：

- 沒有 verified gold 的題目不能進正式 scorer。
- essential exact span miss 保持 miss。
- guard 失敗時 `is_perfect=False`，但保留原始 atomic coverage，另外記錄 guard failure，不用任意常數偷偷扣除 coverage。
- 後續若加入 judge fallback，應新增獨立的 semantic diagnostic 欄位，不能覆寫 `supported_spans`。

### 4.2 Guard 原則

Guard 應在最終生成答案產生後執行，並把結果寫入 `GenerationStageLineage`。目前採 audit-first：先記錄與使 question-level perfect fail，不自動改寫答案；若未來啟用 guard-triggered regeneration，必須對重生後答案再次驗證。

### 4.3 Harness 原則

正式入口必須：

1. 預設只納入 `verification_status=verified`、有 atomic facts（Canary 除外）、非 `[待核]` 且非未回核 `gist` 題目。
2. 將排除題目與原因寫入 manifest。
3. 要求獨立 judge；若刻意允許 shared judge，只能明確標記為 pilot，不能宣稱消除循環論證。
4. 寫出逐筆 `records.json` 與摘要報告，不覆寫既有輸出。

## 5. 實作範圍與未納入範圍

本輪實作：eligibility filter、guard-aware atomic result、RQ1 async main、獨立 judge 接線、逐筆 records／manifest 與測試。

本輪不擅自修改：模型、retrieval top-k、KG、prompt 核心策略、既有題庫 gold、歷史報告數據。這些需要另開 Track B 或重新建 KG 後再做受控消融。

## 6. 驗收、smoke 結果與風險

- 既有基線測試 66 項維持通過；本輪新增後相關測試為 68 項，另針對評測、guard、Ollama deterministic options 的回歸測試共 17 項通過。
- 新增測試需覆蓋：未核驗題排除、空 gold 不得進正式集、guard failure 使 question-level perfect 失敗、shared judge 被標示或拒絕、records 與 manifest 寫出。
- 本文件的外部文獻結論是方法依據，不是本專案效果證據；效果仍須由凍結後的正式 run 取得。

替代模型 smoke 出現「八日」被生成為「八天」的 exact-span miss；檢索召回率仍為 1.0，且 deterministic guard 通過。這正是本設計要保留的區分：它可標記為語義上可能等價的診斷案例，但不能由 judge 自動改寫法律正式分數。正式 Track A 應使用凍結的生成模型、獨立 judge、固定 timeout 與完整 manifest，並另行報告這類 surface mismatch。

本輪另補上 manifest 的 generator／judge／embedding provider-model 與題庫 SHA-256，並禁止同 provider／同 model 的 judge 在未明確 `--allow-shared-judge` 時被標記為正式評測。

### 6.2 Preflight 實作驗收

新增 `services/evaluation_preflight.py`，在連線 Neo4j、載入 baseline index 與呼叫模型前檢查：題目資格、重複 question id、arms、文件範圍、generator／judge 設定、題庫 SHA-256 與 timeout。失敗時只輸出錯誤，不建立半成品結果目錄；pilot 允許 shared judge 時則留下明確 warning。

驗證結果：

- 未設定獨立 judge：`Preflight FAILED`，沒有建立輸出目錄。
- 設定 `qwen2.5:7b` generator + `llama3.2:3b` judge：`Preflight PASSED`，manifest 保存 `preflight.passed=true`。
- Preflight 單元測試：6 項通過。

### 6.3 2026-09-14 Pilot 結果

Pilot 設定為 4 題（`17-Q1`、`18-Q4`、`26-Q5`、`canary-P1`）× 2 方法（M1、M4）× 1 run，共 8 筆；生成模型為 `qwen2.5:7b`，獨立 judge 為 `llama3.2:3b`，單筆 timeout 180 秒。

結果摘要：

| 方法 | 完美原子事實率 | 必要事實召回率 | p50 延遲 | 主要觀察 |
|---|---:|---:|---:|---|
| M1 / B0 | 25.0% | 25.0% | 98.03s | `17-Q1` 成功；`18-Q4` 召回完整但生成端遺漏關鍵百分比；`26-Q5` timeout |
| M4 / K | 25.0% | 25.0% | 180.00s | 3 個法律題 timeout；Canary 拒答成功；KG 查詢出現不存在 relation type warning |

這不是正式基準結論，因為樣本很小且 judge 為本機替代模型；但它已驗證三項重要診斷：

1. M1 可被完整歸因為 Stage 3 generation failure（`18-Q4` retrieval recall=1.0）。
2. M4 目前的主要阻塞是查詢／推理延遲，而不是單純 scorer 缺陷。
3. `26-Q5` 尚未真正測到 inception guard，因為答案在 timeout 前沒有完成；正式評估前必須先補 stage-level timing 或改善 M4／模型延遲。

Pilot artifacts：`reports/rq1_pilot_20260914_v2/manifest.json`、`records.json`、`summary.md`。

### 6.4 暫停點與下次續接計畫

本輪工作於 2026-09-14 暫停，狀態如下：

- Preflight 已完成並接入正式入口。
- Pilot 8/8 筆已完成並保存 checkpoint、manifest、records、summary。
- harness 已能將 timeout 與非 timeout transport exception 轉為結構化 failure record。
- 全部回歸測試：907 項通過。
- 尚未執行完整 `10 題 × 4 arms × 3 runs` 正式基準。

下次續接順序固定為：

1. 加入 retrieval／context／generation／judge 的分階段 latency logging。
2. 審查 M4 查詢使用的 Neo4j relation type 清單，處理 `ETYMOLOGICALLY_DERIVED_FROM`、`ETYMOLOGICALLY_RELATED_TO`、`SENSE_OF`、`SYMBOL_OF` 等不存在型別 warning。
3. 重新執行 M4 小型 Pilot，確認 timeout 是否下降。
4. 只有在 M4 可穩定完成 Pilot 後，才啟動完整正式 Track A。
