## 3. 各任務規格

### F1：不變量清單

**目標**：把 v0.2 §3 的 G1–G9（含使用者的狀態機、屬性、標示不完整原則）寫成**逐條可檢查**的清單。
**每一條必須包含**：編號、白話定義、**來源依據**（簡報哪一頁／使用者哪句話）、**檢查方法**（唯讀 Cypher、檔案檢查或讀碼，**寫出具體查詢**）、**預期值**（符合保證時應該是什麼）、**目前可否檢查**（可／需新資料／需設計決定）、屬〔事實〕或〔提案〕。
**必須涵蓋（至少）**：

1. **G1 來源**：每個 Fact 有來源文件與 chunk／句子範圍；每個 Entity 至少有一條 `HAS_ENTITY` 提及；來源文件版本可辨識（內容雜湊）。
2. **G2 事實 vs 改寫**：標準化改寫（別名登記、代名詞消解）與衍生物（`natural_text`）能否被辨識；引用是否有「經改寫」標記。
3. **G3 身份**：實體是否有穩定 ID；同名不同型別的實體；`aliases` 與 `name` 的一致性；合併是否有紀錄。
4. **G4 關係**：關係型別是否都在宣告詞彙內；`RELATED_TO` 占比與其 `verb` 分布；未解決與一般關係是否可區分。
5. **G5 狀態機**：每個關係是否有狀態、轉換、起訖；同一（主詞,關係,受詞）是否出現「結束後重新開始」的情況（現行模型是否根本無法表示）。
6. **G6 規則**：圖上宣告的不變量有哪些（目前只有 `(kg_id,name)` 唯一）；本清單自己就是候選規則。
7. **G7 來源品質／權威**：來源是否帶屬性；同一條邊是否累積了**互異**的 `verb`／互相矛盾的主張。
8. **G8 證據**：引用欄位是否含抽取時間、模型／提示詞版本；`confidence` 的值分布。
9. **G9 標準化**：實體型別落在核心 52／擴充 939／schema.org 之外（保留原字串）的各自數量；詞彙定義是否分散。
10. **三原則專項**：
    - **屬性／名詞三測試的實測準備**：值節點（數量、金額、等級等）的**度數分布**（連到幾條關係）、被多少個不同來源文件共用——用來檢驗使用者的「互動」判準。
    - **標示不完整**：現行有哪些欄位的空值含意含混（至少檢查 `source_article_no`、型別的原字串保留），並列出「未知／不適用／尚未處理」各需要的標示。
**驗收**：每條都有具體可執行的檢查；標明哪些**現在查不了**（缺資料或需設計）；與 v0.2 §3 的燈號逐項對照（「檢查後可能改變哪個燈號」）；**不連資料庫、不跑任何程式**。
**禁止**：不替使用者定義「預期值」中屬於設計決策的部分（例如狀態機有哪些狀態），遇到就標〔需設計決定〕。

### F2：唯讀實測

**防護（與報告185 C1／報告189 D1 完全相同，缺一不可，違反即停止）**：

1. 開始前先 `ListAgents` 確認沒有其他 session 在用同一 Neo4j／Ollama；記錄結果。
2. 使用既有 `kg2-neo4j` 容器（KG#4 端點 `bolt://localhost:17990`）。**KG#4（`236903cf`）資料是唯一副本，絕對不得 wipe／清空／重建。**
3. **只執行唯讀 Cypher**（`MATCH … RETURN`），`default_access_mode=READ`；沿用前次腳本的寫入關鍵字攔截。
4. **不啟動 Ollama／WSL 模型、不呼叫任何 LLM／embedding。**
5. 執行前後各查一次總節點／總關係／Fact／Entity（應為 57,451／137,873／16,826／12,296），**須相同**，寫入報告。
**做法**：把 F1 中標「可」的項目寫成**一支唯讀腳本**（新增於 `scripts/analysis/`，比照既有分析腳本風格）與對應**單元測試**（對腳本中的純運算部分；不需要連 Neo4j），執行後把**每個數字連同 Cypher** 寫入報告。
**必須回答的具體問題**（我會逐項核對）：

- 有多少比例的 Fact 缺少 `source_*` 欄位？有多少 Entity 沒有任何 `HAS_ENTITY`？
- 同名但型別不同的實體有幾組？`aliases` 與 `name` 的矛盾有幾個？
- `RELATED_TO` 占比（應重現報告187 的 89.1%）與其 `verb` 前 20 名；有多少邊同時累積了**互異的 `verb`**？
- 多少邊的 `citations_json` 有 ≥2 筆來源？其中**來自不同文件**的有多少？（這是「不同來源主張被合併成同一條邊」的實際規模。）
- 引用欄位中含抽取時間／模型版本的比例（預期 0，需證實）；`confidence` 值分布。
- 實體型別落在核心 52、擴充 939、schema.org 之外的各自數量與比例（**使用者想知道「標準化到哪裡」**）；列出 schema.org 之外出現次數最多的前 30 個原字串。
- **值節點專項**：符合「數量／比較句式／序數／等級」樣式的實體有幾個？它們的度數分布（中位數、p90、最大）、被幾個不同文件共用？度數＝1 的占比？（用以檢驗使用者的「互動」判準：值節點是否大多只連一條關係。）
- 是否存在「同一（主詞,關係,受詞）在不同文件中矛盾」的明顯案例（只列出，不裁決對錯）。
**驗收**：Cypher 逐條列出供我檢查唯讀；前後總數相同；每個數字能由附錄查詢重現；無 LLM／embedding 呼叫；`scripts/` 新增腳本不改任何 production 程式；全量 pytest **≥1582 passed、0 failed**（含新測試）；腳本匯入不得改 `os.environ`（比照 B1／C3／D2 的教訓，須有測試）。
**禁止**：任何寫入；啟動 Ollama；重抽；改題庫；改 production 程式；把查詢結果解讀成「已違反簡報」——**只報數字，判斷由規劃對話與使用者做**。
**停止條件**：防護任一條無法滿足；前後總數不一致；發現需要寫入或 LLM 才能回答；發現其他 session 在用同一 Neo4j。
