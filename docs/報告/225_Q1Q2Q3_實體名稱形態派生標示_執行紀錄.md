## 1. Q1：`services/semantic_marks.py::mark_entity_name_shape()`

**位置**：`services/semantic_marks.py` 末尾新增（匯入仍只有 `__future__`／`re`／`typing`，與修改前相同；既有函式節點 `ast.dump` 全部不變，只新增 3 個函式與 10 個常數）。

**值域（PROVISIONAL，不與既有標示值域重疊，測試守住）**：

| 值 | 條件 |
| --- | --- |
| `疑似子句（長度＋特徵）` | 名稱原字串長度 ≥ 門檻，且命中至少一項字面特徵（報告223「強候選」） |
| `疑似子句（僅長度）` | 長度 ≥ 門檻，無任何特徵 |
| `非子句` | 長度未達門檻（即使含特徵，如「勞工之」） |
| `無法判定` | 空白／`None`／非字串（含全形空白） |

**重用報告223 定義、不自行發明**：門檻預設 **12**（`NAME_SHAPE_DEFAULT_THRESHOLD`，參數可改 8／20）；三項特徵（條文用語十個關鍵字、標點括號、數字加單位）的關鍵字與正則逐字複製自 `scripts/analysis/clause_entity_quantify.py`；長度用**原字串長度（不 strip）**，與 O1 一致。單元測試以逐項比對（關鍵字、兩個正則 pattern、主門檻、特徵名稱順序）與在名稱語料上對照 O1 的 `is_strong_candidate`／`name_features`，守住兩處不漂移。

**設計取捨（寫明理由）**：區分「僅長度」與「長度＋特徵」兩級時，回傳**單一字串**（四值之一）而非 tuple 或結構——trace 與評測 JSON 保持扁平、與 M1／N1 的標示風格一致；兩級都以「疑似子句」開頭，並提供 `is_suspected_clause_shape()` 判斷。報告223 的定義可無歧義轉成函式（長度門檻與特徵皆為純字面規則），**未觸發停止條件**。

**誤判風險（已寫入 docstring）**：長名稱不一定是子句——「勞動基準法施行細則第三十五條」會被判為「長度＋特徵」（已知誤判，有測試記載）；「之」「得」「其」等單字特徵更常出現在合法名稱；報告223 O2 的 50 筆草稿中合法長名稱僅 6%、無法判斷 30%（草稿，未經使用者確認）。**不得據以過濾、降權或改寫實體名稱，不得寫回任何儲存資料。**
