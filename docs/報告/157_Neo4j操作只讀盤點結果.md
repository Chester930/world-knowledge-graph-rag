## 2. 方法與限制

**三個獨立來源**（互相交叉，見 §8）：

| 來源 | 內容 |
| --- | --- |
| A 執行點 | AST 找 `.execute_query／.execute_read／.execute_write／.session(／.begin_transaction(`、接收者名稱含 `session／tx` 的 `.run(`，以及「以參數傳入查詢字串的包裝函式」的呼叫點 |
| B Cypher 字串 | 函式內（含可解析的模組層級常數、**略過 docstring**）含 Cypher 子句的字串常數；由此抽出節點標籤、關係型別、Neo4j 專屬功能 |
| C 簽名 | 參數含 `AsyncDriver`／名為 `driver`／`session`／`tx` 的函式（用來找「只轉手 driver、不自己寫 Cypher」的函式，見 §6） |
| 對照 | 純文字 grep（樣式：`execute_query`、`.session(`、`session.run`、`tx.run`、`GraphDatabase`、`db.index.vector`、`MERGE (`、`MATCH (`）的檔案清單與行數 |

**掃描範圍**：整個 repo 的 `.py`，排除 `tests/`、`data/`、`docs/`、`.claude/`、`node_modules`、虛擬環境。`scripts/` 與根目錄腳本全數納入並**分開標示**（報告155 只要求「非一次性腳本」，何者算一次性腳本屬主觀，故不自行篩選，全列）。

**限制（誠實侷限）**：

1. **標籤／關係／功能欄是由字串常數抽出的**。f-string 中 `{...}` 內插的部分（例如 per-KG 的 `Fact_<uuid>` 標籤、動態關係型別）在 AST 中不是字串常數，**抽不到**；這些以「per-KG 動態標籤」「動態關係型別」人工補註（§4.2）。
2. **「操作種類」欄由人工依函式內容分類**（74 列，逐一閱讀 Cypher 摘要）。
3. **讀／寫欄**：機器判定（有 `MERGE／CREATE／SET／DELETE／REMOVE` 即為寫），DDL 與包裝函式已人工覆寫。
4. 只看**靜態存取位置**；「某函式實際被哪些路徑呼叫、頻率多高」屬 T4／執行期問題，本報告不涉及。
5. 不含 `tests/` 內直接對 Neo4j 的測試（有 `tests/core/test_embedding_migration.py` 等，已被排除在基準之外）。

## 8. 測試補丁觀察（re-export 陷阱依據）

1. **補丁綁在「使用者模組」的名稱上，不是定義處**（這是搬移時最容易出事的地方）：`tests/routers/test_agent.py` 以 `<agent>.vector_search_facts`×18、`<agent>.bfs_query`×17、`<agent>._find_seed_entities`×18、`<agent>.vector_search_entities`×2 補丁；`tests/services/test_extraction_worker.py` 以 `services.extraction_worker.merge_triples_to_graph`×3；`tests/services/test_expand_worker.py` 以 `services.expand_worker.backfill_related_to_edges`×2；`tests/test_main.py` 以 `<main_module.svo_service>.create_entity_index` 等。若 `GraphStorePort` 實作搬走這些函式，**只有指向「使用者模組名稱」的補丁仍有效**；指向 `svo_service.X` 的補丁（`<svc>._fetch_entity_candidates`、`<svc>.merge_entity`、`<svc>._execute_with_constraint_retry`，共 3 個測試檔）搬移後會失效。
2. **多數存取函式沒有被補丁**：55 個正式程式函式中僅 **19** 個被 `tests/` 以名稱補丁（詳見 §3 表最後一欄）；其餘由「假 driver」測試覆蓋——`tests/` 內含 `execute_query` 的檔案共 12 個（`tests/services/test_svo_service.py` 20 處、`tests/routers/test_agent.py` 4 處、`test_svo_service_cfg_wiring.py` 2 處，其餘各 1 處），以 `AsyncMock`／假物件替換 `driver.execute_query`。這類測試**不受**函式搬移影響，但**受 driver 型別／`execute_query` 介面影響**。
3. `KGRepository.get` 等名稱過於通用者在 §3 標「未判定」，避免誤配。
