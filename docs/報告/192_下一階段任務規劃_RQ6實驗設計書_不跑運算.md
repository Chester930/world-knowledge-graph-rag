## 3. 各任務規格

### E1：RQ6 實驗設計書

**目標**：讓使用者只需決定「跑或不跑」。設計書要寫到：若使用者說「跑」，執行對話可直接照做，且**採用／不採用的判定規則在跑之前已經凍結**（避免事後挑指標）。
**內容（每一節標〔事實〕附 `檔案:行號`／〔提案〕／〔無資料〕）**：

1. **被測機制的現況**〔事實〕：論文 `05` §5.2.3 RQ6 列（含 Z1 更正後的基準：L0／L1、每 seed `per_seed_limit=30`、無 L2）；程式碼中 L2（`prize_top_k`、`question_vector`、`_score_lines_by_embedding`，`routers/agent.py` 約 `:129`、`:512–542`、`:578`）與 `services/retrieval/bfs.py` 的對應參數；`chat()` 主路徑**目前沒有傳** `prize_top_k`／`question_vector`／`embedding_provider`（約 `:1355-1361`）。
2. **最小接線方案**〔提案〕：要讓 `chat()` 能以參數／KGConfig 開關 L2，最少要改哪幾處、改動量、是否影響預設行為（**預設必須維持關閉，與現行基準逐位元相同**）；列出「不改 production 的替代方案」（例如以評測 harness 直接呼叫 `bfs_query(prize_top_k=…)` 與既有檢索函式重組，不動 `chat()`），並比較兩者的代價與外部效度。**不實作。**
3. **自變項**〔提案〕：`prize_top_k` 的候選值（依既有每題檢索量分布決定，例如以「BFS 後三元組數」的分位數校準，**需說明分布來源**；若只有部分資料就標〔無資料〕並列出取得方式）、基準臂（`None`）。
4. **應變項與資料來源**：
   - **主要**（二元）：凍結 42 題中**檢索面相關的 19 題**（報告179）的達標與否——沿用既有評分器，**並列出評分器已知盲點**（偽陰性下界 ≥7.2%、偽陽性 ≥3.4%、不檢查新舊法歸屬）對 RQ6 的影響。
   - **次要**（連續）：最終 context 長度（字元／token）、`gold` 片段是否仍在 context 內（**召回保持率**，可用既有 `retrieval trace`／`kg_source_recall_probe` 一類離線方法，不需重跑生成）、延遲、（可選）SNR。**逐項說明現有 harness 是否已記錄、是否要新增記錄欄位。**
5. **統計與檢定力**〔事實＋推論〕：二元用精確 McNemar（引用報告179 §3 的表）；連續量用配對 Wilcoxon／t，並估算 n=42（或 19）下可偵測的標準化效應量（**寫出公式與假設**）。
6. **採用規則（跑前凍結）**〔提案〕：例如「召回保持率不得低於基準 X% 且 context 長度降幅≥Y% 且主要二元指標不得出現顯著退步」；X、Y 由設計書**依既有資料提出建議值與理由**，供使用者拍板。**明寫：未過規則＝不採用，不得事後換指標。**
7. **資源與時間**〔事實＋提案〕：需要啟動的服務（Neo4j、Ollama、WSL 記憶體陷阱——見記憶中「雙 Ollama／WSL 記憶體」注意事項，引用報告或記憶中的具體限制，**不憑印象**）；每個 k 值的預估 run 時間（引用報告175 的 1.2–1.7 h／run，並說明該數字的出處與適用條件）；是否與其他 session 共用資源（需先 `ListAgents`）。
8. **風險與回退**〔提案〕：接線若改了 production 的預設行為怎麼偵測（回歸測試 1582 為基準）；L2 的 embedding 呼叫失敗時的降級；結果可能「準確率無差異」時，論文如何誠實呈現（報告61：論文定位＝診斷 KG 何時有增益）。
9. **待使用者裁示清單**：跑或不跑；採「改 `chat()`」或「harness 內重組」；X、Y 與 k 值；是否允許啟動服務與預估時間預算。
**驗收**：每個〔事實〕附 `檔案:行號` 且我抽查對得上；沒有任何數字憑空出現（無資料就寫無資料）；採用規則給出建議值**與理由**；全文零程式變更、零論文變更、零題庫變更；`git diff --check` 通過。
