## 2. 兩個獨立的根因，不可混為一談

### 2.1 檢索層（BFS + 語意 Fact 搜尋）——本輪測試暴露的主要瓶頸

**7 題中 7 題 BFS 圖遍歷皆找到 0 筆三元組**——即使問題用詞（如「婚假」「事假」「特別休假」）與條文原文高度重疊，種子實體比對（`_find_seed_entities`，字面比對）仍完全沒有命中。語意 Fact 搜尋（`vector_search_facts()`）部分緩解，但**多次未能把 Top-5 排到單一最相關的那條**（案例：Q5 完全漏掉核心的第 3 條、Q6／Q7 漏掉最直接相關的那句）。這是本次測試裡導致答案錯誤或不完整的**主要根因**，與本次實作的 `Document`／`LawArticle`／接地性核對三項改動無關，是既有 BFS＋向量檢索機制本身的召回率問題。

### 2.2 生成層——接地性核對機制的實際表現

排除檢索層問題後，單看「核對機制有沒有做到它設計要做的事」：

- **抓到生成階段憑空捏造**（Q1、部分 Q2、Q7）：✅ 表現符合預期，這正是報告 16 設計要解決的問題。
- **正確認可誠實的『無法確定』回答**（Q4、Q6）：✅ 沒有錯誤懲罰誠實回答。
- **假陰性**（Q3 一處）：⚠️ 把逐字引用的檢索事實誤判未接地，v1 用單次 LLM 判斷、非 RAGAS 原始的獨立 claim decomposition 步驟，判斷穩定性有限，屬已知的 v1 簡化代價（見報告 16 § 8 誠實侷限）。
- **結構性限制，非 bug**（Q5）：⚠️ 核對機制驗證的是「忠於檢索到的證據」（faithfulness），不是「答案本身對不對」（correctness）——這是 RAGAS Faithfulness 指標本身的既定定義範疇，**檢索到錯誤/不完整的證據時，忠實於證據的答案仍可能是錯的**，接地性核對無法、也不該被期待能糾正上游檢索的召回率問題。

## 3. 額外發現：SVO 抽取對條件式條文的處理

Q3 對應的 N0030018 第 2 條是「原則 X，但例外 Y」的條件式結構（原則不少於 6 個月，但有短期需求者可少至 30 日），檢索到的事實只反映了「例外」子句，主要規定（6 個月原則）未出現在任何 Top-5 結果中。這**可能**是切塊或 SVO 抽取階段對條件式長句的處理限制，非本次接地性核對範圍，記錄於此供後續獨立排查（不在本報告下判斷是切塊粒度、代名詞消解，或抽取 prompt 本身的問題，需要另外挑樣本查證）。

## 4. 結論：品質是否達標？

分兩個維度分別回答，不可合併成單一「達標／不達標」的判斷：

- **接地性核對機制本身**：v1（句子拆解＋單次 LLM 判斷）在本輪 7 題的真實測試中，於「檢索到但生成階段捏造」與「誠實承認不確定」兩種情境下表現符合設計預期；已知一項假陰性（v1 簡化的已知代價）與一項結構性限制（faithfulness ≠ correctness，非本機制能力範圍）。**達到 v1 設計目標**，但不應被誤用為「答案正確性的保證」。
- **端到端問答品質（含檢索層）**：本輪測試 7 題中僅 1 題（Q4）完全正確、2 題誠實迴避未答錯（Q6、Q7）、1 題誠實但引用了查無依據的法條（Q2）、3 題答案錯誤或有嚴重遺漏（Q1、Q3、Q5）。**尚未達到可靠問答的標準**，主因是 BFS 種子比對在本場景近乎全數失效（7/7 題 0 三元組），語意 Fact 搜尋的召回率也不穩定——這是既有檢索機制（非本次三項實作）的既有限制，需要獨立排查與改善才能讓整條管線的答案品質達標，非接地性核對機制能單獨解決。

## 5. 明確排除本報告範圍

- BFS 種子實體比對為何在本場景近乎全數失效——需要另外查看 `_find_seed_entities()` 的字面比對邏輯與本 KG 的實際 Entity 命名，非本報告排查。
- 語意 Fact 搜尋召回率不穩定的根因——是 embedding 模型、top_k 設定，或事實文字化（`_verbalize_fact()`）的措辭問題，需要另外查證。
- Q3 揭露的條件式條文抽取限制——需要另外挑樣本查證是切塊、代名詞消解，或抽取 prompt 的問題。
- 本報告的 KG（`b3477944-...`）暫不刪除，供後續排查直接查詢使用。
