# 報告256：實體合併衝突對檢索的實際曝險量測——凍結評測 K1 trace × KG#4（唯讀）

> **日期**：2026-10-02
> **性質**：規劃對話親自執行的**唯讀分析**（使用者「依照建議繼續」＝做報告255 §7 的方案 B「量測對檢索的實際影響」）。KG#4 全程只經 `ReadOnlyRunner`（純 MATCH）；前後總數相同（`totals_stable＝true`）；`kg2-neo4j` StartedAt 仍為新基準 `2026-10-02T11:09:32.79429649Z`；未呼叫 embedding provider；評測 records 為**離線讀取**。
> **依據**：[報告255](255_方案B變動溯源與實證_來源chunk逐字比對.md) §3.5（311 個實體現名與別名含關鍵字詞／法規指涉衝突）與 §7。
> **標記**：〔事實〕＝程式計算；〔判讀〕＝規劃對話判斷；〔推論〕＝尚未驗證。

## 1. 結論

**在這份 42 題資料上，看不出實體合併衝突與檢索失敗有關。**
1. 進 prompt 的證據約 **17%（Fact）／14%（三元組）** 連到可疑實體，但**通過題與失敗題的曝險率差距不顯著**（每題平均 12.8% vs 17.5%，排列檢定 p＝0.26，差距 95% 信賴區間 −1.0～+10.9 個百分點）。
2. **含標準答案片段的 prompt 證據幾乎不碰這些實體**：32 項（跨執行計次）中只有 2 項曝險——且是**同一題 `18-Q3` 兩次執行中的同一句三元組**——**0 項**屬於「抄本與實體名稱不一致」（方案 B 會更動）的那一類。
3. 因此報告255 的實體合併問題，**目前沒有證據顯示它是這批評測失敗的主因**；這不等於證明無影響（見 §6）。
4. **不建議為此現在修正管線或圖譜**；補守衛（報告255 方案 A）降為「新抽取的低優先衛生項」。

## 2. 方法（〔事實〕）

腳本 `scripts/analysis/kg4_conflict_exposure.py`（KG#4 唯讀；其餘離線）：

1. **評測資料**：凍結評測 K1（`top_k=40`）8 個 stage 目錄的 records，共 **78 筆有效執行、42 題**；每筆含 `retrieval_trace`（每個證據的 `kind`／`rank`／`text`／來源／`in_prompt`）。通過／失敗分組取自 `summary_final.json`：stable_pass＋single_pass＝通過 **12 題**、stable_fail＝失敗 **28 題**、unstable **2 題**。
2. **可疑實體**：報告255 的實體別名集合，保留現名與別名衝突類別為「關鍵字詞變動」或「法規指涉變動」者，共 **311 個**（295∪22，扣除重疊）。
3. **把證據對回實體**：Fact 項以（`source_doc_id`、`source_svo_chunk_index`、`fact_text`）對回 `Fact` 節點，取 `HAS_SUBJECT`／`HAS_OBJECT` 實體；三元組項（trace 內是邊的 `natural_text` 自然語句）以 `natural_text` 反查邊的兩端實體。
4. **指標**（只計 `in_prompt＝true` 的證據）：①曝險＝任一端是可疑實體；②「抄本不一致」＝Fact 的扁平 `subject`／`object` ≠ 所連實體現名（即方案 B 會更動者）；③含標準答案片段＝證據文字（去空白）包含該題任一 gold `exact_span`。
5. **統計**：每題算一個曝險率（曝險項／已匹配項），通過 vs 失敗用排列檢定（20,000 次洗牌）與 bootstrap（10,000 次），避免把同一題內相依的證據當獨立樣本。

## 3. 結果（〔事實〕）

### 3.1 對回實體的覆蓋

進 prompt 證據共 **2,836 項**：Fact 2,325 項（對回 **2,241＝96.4%**）、三元組 511 項（對回 **396＝77.5%**）。三元組有 22.5% 無法以 `natural_text` 反查到邊（可能文字經後處理或對應多邊），這部分**未納入**曝險計算。

### 3.2 曝險

| 項目 | 數量 | 比例（對回者） |
| --- | --- | --- |
| Fact 連到可疑實體 | 381／2,241 | **17.0%** |
| 三元組連到可疑實體 | 57／396 | **14.4%** |
| Fact 屬「抄本與實體名稱不一致」（方案 B 會更動） | 168／2,241 | **7.5%** |

幾乎每題都有曝險（41／42 題至少一項；唯一為零的是 `17-Q6`）。被標為曝險的例子多是「外國人」「中央主管機關」「事業單位」這類**高頻樞紐實體**（見 `data/analysis/kg4_conflict_exposure_20261002.json` 的 `failing_question_examples`）。

### 3.3 通過 vs 失敗

| 分組 | 題數 | 進 prompt 已匹配項 | 曝險項 | 抄本不一致 Fact |
| --- | --- | --- | --- | --- |
| 通過 | 12 | 584 | 76（13.0%） | 30 |
| 失敗 | 28 | 1,864 | 332（17.8%） | 108 |
| 不穩定 | 2 | 189 | 30（15.9%） | 30 |

每題曝險率：通過平均 **12.8%**（中位 14.1%）、失敗平均 **17.5%**（中位 14.3%）；差 **+4.7 個百分點**，排列檢定雙尾 **p＝0.256**，bootstrap 95% 信賴區間 **[−1.0, +10.9] 個百分點**——**無法與 0 區分**。（逐項合併計的 13.0% vs 17.8% 看似有差，但同一題的證據彼此相依，以每題一個數字檢定才是合理做法。）

### 3.4 含標準答案片段的證據

32 個含 gold 片段的 prompt 證據（**跨執行計次**：通過題 8、失敗題 24）：**曝險 2 項**——兩項都來自失敗題 `18-Q3`，是該題兩次執行中**同一句**三元組標準答案句，所以獨立證據只有 1 句；**抄本不一致 0 項**。

## 4. 解讀（〔判讀〕）

1. 實體合併衝突確實存在（報告255），但在目前 42 題的檢索結果裡，**標準答案證據幾乎不經過這些實體**；失敗題的 prompt 裡，曝險的是大量一般樞紐證據，更像背景噪音而非缺答案的原因。
2. 這與先前診斷一致：報告57 §4.21 把 20 題檢索失敗歸因為「抽到但破碎／丟限定條件」「排名太後」等，**與實體合併無關**。
3. 方案 B 若套用，會更動的 Fact 只佔進 prompt Fact 的約 7.5%，且**沒有任何一個承載標準答案**——也就是說，即使 B 是「無害」的，它在這批評測上**也沒有可預期的益處**，與「不套用」的結論一致。

## 6. 限制與誠實揭露（請勿過度引用）

- **只有 42 題、通過題僅 12 題**；檢定力低，「無顯著差異」不等於「沒有影響」。
- 評測是 **K1（`top_k=40`）**，不是 `top_k=20` 的凍結基準本身（基準無 trace）；組成不同（Fact 較多、BFS 較少）。
- 三元組對回率只有 77.5%；未對回者未計。
- 「可疑實體」是**啟發式**（含誤報，樞紐實體尤其如此），所以曝險率是**上限傾向**；同時它**沒有量測 BFS 透過錯併實體引入噪音的反事實效應**（需要對照實驗才能回答）。
- 「含標準答案片段」是**去空白子字串比對**（近似）；沒有人工逐項確認。
- 本報告只涵蓋**檢索進 prompt 的證據**，沒有評估生成階段。
- 凍結評測是**法規問答**評測；其他類型題目的影響未知。
