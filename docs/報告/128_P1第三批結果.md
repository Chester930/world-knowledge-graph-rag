## 1. 執行範圍與檔案變更

第二段只修改任務書 §5、`services/document_record_service.py`、任務書允許新增的
`tests/state/test_document_sm_single_entry.py`，以及本成果報告。沒有修改呼叫端、既有測試、
`state/document_sm.py` 或其他 production 檔案；沒有啟動 Neo4j／Ollama／server，沒有執行匯入或重抽。

在 `document_record_service.py` 新增兩個私有入口：

- `_transition_extraction(record, event)`：以 `ExtractionStatus` 與 `document_next_status()`
  決定抽取狀態。
- `_transition_normalization(record, event, target)`：以 `NormalizationStatus` 與
  `normalization_next_status()` 決定標準化狀態。

六個既有寫入點均改由入口完成：`init_record` 的 reparse reset、
`update_normalization_progress`、`reset_extraction_progress`、`record_chunk_completed`、
`mark_extraction_failed`、`append_assignment`。公開函式簽章、回傳、例外與欄位更新順序維持不變。

非法 normalization status 的相容分支採核准後更正版本：

```python
if event is NormalizationEvent.SET_STATUS and target not in valid_targets:
    record.normalization_status = target
    return
```

因此 `REPARSE_CHUNK_COUNT_CHANGED` 且 `target=None` 不會落入相容分支，仍由轉移表重設為
`not_started`。X1（`failed` 後完成部分 chunk 變 `processing`）與 X3（缺記錄回傳 `None`）均保留。
