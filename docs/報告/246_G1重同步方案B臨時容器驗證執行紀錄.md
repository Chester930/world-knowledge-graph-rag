## 3. W2：方案 B 原型

驗證腳本內的 `resync_fact_flat_properties(driver, kg_id, *, dry_run=True, sync_rel_type=False)` 先以 `HAS_SUBJECT`／`HAS_OBJECT` 讀取，再只對變動的三個欄位用批次 `UNWIND` 寫入。`sync_rel_type=True` 只接受端點間恰好一條同時帶 `kg_id` 與 `citations_json` 的關係邊。

### 3.1 W1 小圖

| 統計 | dry-run | 實際套用 |
|---|---:|---:|
| `subject_changed` | 2 | 2 |
| `object_changed` | 0 | 0 |
| `rel_type_changed` | 0 | 0 |
| `rel_type_skipped_multi_edge` | 0 | 0 |
| `rel_type_skipped_no_edge` | 0 | 0 |
| `unchanged` | 1 | 1 |
| `facts_without_links` | 0 | 0 |

- `dry_run` 與緊接的實際統計完全相等，dry-run 前後 Fact 屬性摘要相同。
- 第二次套用三個變更欄位皆為 0；只剩 `unchanged=3`。
- 前後節點數、邊數、Entity 名稱、關係型別／屬性與 Fact 非三目標屬性摘要均相同，`only_three_attributes=true`。

### 3.2 邊界與隔離

另建合成 KG 測試空字串／`None`、名稱含空白、已一致、缺一或兩條 HAS 邊、唯一邊、多邊與無邊：

| 統計 | dry-run＝實際 |
|---|---:|
| `subject_changed` | 4 |
| `object_changed` | 3 |
| `rel_type_changed` | 1 |
| `rel_type_skipped_multi_edge` | 1 |
| `rel_type_skipped_no_edge` | 2 |
| `unchanged` | 1 |
| `facts_without_links` | 2 |

邊界圖的 dry-run 不寫入、第二次三目標變更為 0、節點／邊數與非三目標屬性均不變。對 KG-A 執行後，另一個含過時 Fact 的 KG-B 的 Fact 與圖摘要完全不變。`unchanged` 是「本次沒有三目標變更」的計數，因而可與保守跳過統計同時出現；這不影響 dry-run／實際等式或冪等判定。
