## 2. Demo 1：SVO 抽取可信任性驗證

### 核心論點

> 「圖譜裡每一條事實，都不是 LLM 憑空生成的，而是有明確的來源文件、來源段落、甚至來源句子範圍可以逐字對照回原文。」

這是本系統設計上的核心承諾（citations_json 追溯機制），也是跟「LLM 直接問答容易幻覺」做出區隔的關鍵賣點。

### 操作步驟

**① 在 Neo4j Browser 執行以下查詢**，秀出一條已驗證過、乾淨完整的事實：

```cypher
MATCH (s:Entity {name: "勞動基準法第三十六條第四項指定行業"})-[r]->(o:Entity)
RETURN s.name AS 主詞, type(r) AS 關係, o.name AS 受詞, r.citations_json AS 來源追溯
```

預期結果（一條邊）：

- 主詞：`勞動基準法第三十六條第四項指定行業`
- 關係：`DEFINED_AS`
- 受詞：`經目的事業主管機關同意與勞動部指定之行業，得於每七日週期內調整例假（最長連續工作12天）：1. 配合重要年節、活動疏運期間之客運及貨運運輸業。2. 出國執行職務之旅行業、新聞出版與廣播電視業`
- `citations_json`：`source_svo_chunk_file: "svo-chunk-003-of-004.md"`、`source_sentence_start: 7`、`source_sentence_end: 11`

**② 對照原文**——打開這個檔案（在 worktree 的 `workspace/deb24e7c-c012-4398-9261-c813cb60b197/勞動基準法第三十六條第四項指定行業公告_中華民國政府發布/svo-chunk-003-of-004.md`），內容是：

```
【勞動基準法第三十六條第四項指定行業公告 (調整例假/放寬七休一)】
主管機關：中華民國勞動部
經目的事業主管機關同意與勞動部指定之行業，得於每七日週期內調整例假（最長連續工作12天）：
1. 配合重要年節、活動疏運期間之客運及貨運運輸業。
2. 出國執行職務之旅行業、新聞出版與廣播電視業。
```

**逐句對照給專家看**：Neo4j 裡的事實文字，跟原文第 7-11 句幾乎逐字對應——這不是巧合，是系統設計上刻意保留的追溯鏈路。

**③（強烈建議）現場再挑一條，證明這不是唯一準備好的個案**：請專家隨意在 Neo4j Browser 執行：

```cypher
MATCH (s:Entity {kg_id: "deb24e7c-c012-4398-9261-c813cb60b197"})-[r]->(o:Entity)
WHERE r.citations_json CONTAINS "source_sentence_start"
RETURN s.name, type(r), o.name, r.citations_json
ORDER BY rand()
LIMIT 5
```

任選一條，依 `citations_json` 裡的 `source_svo_chunk_file` 到對應文件資料夾找同名檔案對照——現場示範「這套追溯機制對任意一條邊都成立，不是挑過的」。

> ⚠️ **誠實提醒**：目前抽取品質並非 100% 完美——實體解析（同名合併）偶爾會把語意相近但不同來源的內容合併到同一個實體節點上（例如「跨日班」這個詞同時被住院醫師輪班與航空機組員的規定使用）。如果現場隨機挑到這類例子，可以坦然說明：這是實體對齊機制（編輯距離→cosine 相似度→LLM 仲裁）目前的已知限制，追溯機制本身仍然完整可查，只是「這條事實該不該合併成同一個實體」是另一個獨立問題，且已有明確的改進路徑（第五章消融實驗）。

### 可以補充的技術背景（若專家追問機制本身）

- 三元組抽取：LLM 逐塊抽取主詞-關係-受詞，關係型別限定在受控詞彙表（33 類，改編自 ConceptNet 5.5）。
- 型別判斷有雙重驗證機制（SIM／COMPARE／ESCALATE3）：embedding 相似度比對 + 不一致時二次 LLM 仲裁。
- 同一事實若被多個來源片段重複提及，會收斂成同一條邊、來源清單累加（不會產生重複邊）。
- 動態擴充機制（EXPAND）：受控詞彙表之外的新關係類型，會先進候選池、經 HDBSCAN 分群 + LLM 判斷 + 人機一致率門檻決定是否核准，不是每次都放行未知類型。

## 3. Demo 2：圖譜查詢問答（暫時版本）

### 核心論點

> 「圖譜不是死的資料庫，可以直接用自然語言問問題，系統會先去圖上找相關事實，再讓 LLM 根據這些事實回答——回答有依據時會清楚引用，沒有依據時也會誠實告知，不會假裝有憑有據。」

**這裡務必明確定位**：這是為了 demo 先接的**堪用版本**，跳過了正式設計中的 `ConceptNode` 語意路由層（RQ2，尚未設計完成），改用最直接的字面比對找種子實體。跟專家說明時建議直接講清楚這個定位，不要包裝成正式版本——誠實說明反而更能顯示研究的嚴謹度。

### 操作步驟

1. 打開 `http://localhost:8010`，左側清單點選 **「排班與工時法規」**（或「請假與薪資法規」）。
2. 在下方聊天框輸入以下問題（承接 Demo 1 剛展示過的同一條事實，呼應「這個事實不只存在圖上，還真的能被用來回答問題」）：

   > **勞動基準法第三十六條第四項指定行業，可以在什麼條件下調整例假？**

3. 預期會即時串流出這樣的回答：明確引用「配合重要年節、活動疏運期間之客運及貨運運輸業」「出國執行職務之旅行業、新聞出版與廣播電視業」「最長連續工作12天」——跟 Demo 1 秀過的原始事實一致。

> ⚠️ **誠實提醒（若專家問到準確率或已知問題）**：
> - 目前找種子實體是「問題字串裡有沒有整段出現既有實體名稱」的字面比對，不是語意/向量檢索——措辭差異較大的問題可能命中不到已存在的相關事實（例如口語化問法）。
> - 找不到依據、退回一般知識時，本地小模型（`qwen2.5:7b`）偶爾對具體數字（例如法定比例、天數）的記憶不準確，即使已加上「沒有依據就不要猜數字」的指示，遵從度也不是 100%——這是本地小模型指令遵從能力的已知限制，不是系統設計缺陷；根本解法是讓抽取覆蓋率提高，讓更多問題都能落在「有依據」的路徑上。
> - 正式的雙層路由（`ConceptNode` 語意路由 → `BFS` 圖遍歷 → 自我精煉迴圈）仍待第 3.2 §a 節設計完成後才會取代這個暫時版本。
