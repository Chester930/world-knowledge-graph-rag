## 2. 前置查證（2026-09-04/05）

### 2.1 現行 KG 實測：這次重抽沒踩到，但守衛邏輯確實有漏洞

直接查詢 c15949bf（已完全重抽的 N0070020）：「每一型式」只有一條邊
（`→ 新臺幣八千元`），「每增加一種型式」完全不存在於圖中——「四千元」那筆事實
這次被抽成完全不同、逐字抄錄原文的長 subject（「同時申請多種型式且皆屬相同
危險性機械或設備種類者」），跟「每一型式」編輯距離差很多，這次沒有觸發問題。
**推測是 `qwen2.5:7b` 非決定性（報告20 已確立）讓這次的措辭恰好避開碰撞**，
不是問題已解決。

### 2.2 根因：`resolve_entity_name()` 的守衛是不對稱的

`_MEASURE_PATTERN` 守衛（報告25 發現3/發現C）只檢查**正在解析的新名稱 `name`
本身**，不檢查候選清單裡的既有實體：

- 「每增加一種型式」含「一種」（數字＋單位），若它是新進來的 `name`，會命中
  `_MEASURE_PATTERN` 而提早返回，不會被合併——安全。
- 「每一型式」不含任何「數字＋清單內單位」組合（「一」後面接「型式」，不在
  `_MEASURE_PATTERN` 清單內），**完全不受保護**——若它是新進來的 `name`、
  「每增加一種型式」已在候選清單裡，`_edit_ratio`＝0.727 ≥
  `ENTITY_DEDUP_EDIT_RATIO_THRESHOLD`（0.70）會直接合併。

**是否觸發純屬「誰先進圖」的運氣**，不是穩定行為。

### 2.3 這是新的一類問題，不是量詞問題

「每一」vs「每增加一」不是「同單位不同數值」（`_QUANTITY_PATTERN`／`_MEASURE_PATTERN`
處理的量詞類），是**基礎量 vs 遞增量**——「增加」這個**範圍修飾詞**改變語意，
表面極相似、語意相反。`_MEASURE_PATTERN` 的「數字＋單位」樣式規則結構上抓不到
這類不含數字的短語，需要新的偵測邏輯，不是擴充既有樣式就能涵蓋。

### 2.4 第三種變體（2026-09-05 真實診斷）：裸數字比較詞——報告26 #3 Q8 的真正根因

報告26 §4 #3「多跳/區間比對推理」原本的假設是「模型不會自己推『5 落在 1 以上未滿
10 → 係數 2』」（Q8 的問法見報告26 §1 第8題）。討論時直接查碼＋真實重跑診斷，發現
根因完全不是生成端推理：

**第一步——直查 c15949bf 現行圖譜**（N0060004 容許暴露標準第3條變量係數表）：
只有 2 個「容許濃度」範圍節點，其中一個節點同時掛著**三個互相矛盾**的變量係數
（`100 以上，未滿 1000 的容許濃度` → `3`／`2`／`1.25` 三條邊都存在），`1 以上，
未滿 10 的容許濃度`（Q8 要的那一條）**完全不存在於圖中**。

**第二步——對同一 chunk 原文重跑 `extract_svo_triples()`**（純診斷呼叫，不寫入
資料庫，繞過既有 task_queue／drain）確認 LLM 抽取本身完全正確、完整：

```
未滿 1 的容許濃度              → 變量係數為 3
1 以上，未滿 10 的容許濃度      → 變量係數為 2   ← Q8 要的正是這條
10 以上，未滿 100 的容許濃度    → 變量係數為 1.5
100 以上，未滿 1000 的容許濃度  → 變量係數為 1.25
1000 以上的容許濃度            → 變量係數為 1
```

**結論**：5 筆抽取皆正確，但寫入 Neo4j 時被 `resolve_entity_name()` 逐一模糊合併
成 2 個節點。原因與 §2.2 完全同構——這 5 個主詞共用「以上，未滿」「的容許濃度」
長共同子字串，`_edit_ratio` 必然超過 0.70 門檻，但數字（`1`／`10`／`100`／`1000`）
後面接的是「以上」「未滿」「的容許濃度」，**不是** `_MEASURE_PATTERN` 認得的任何
單位（日／月／年／元／歲／人／條／款…），現有守衛結構上抓不到「裸數字＋比較詞」
這種寫法——法規常見的門檻/級距表（變量係數表、罰鍰級距、年資級距等）幾乎都是這種
句式。

**⚠️ 這個 bug 是「現在進行式」，不是歷史遺留**：查 `task_queue.db`，N0060004 全部
11 個 chunk 在**當前這輪全量重抽**（c15949bf，含發現3/4/C 全部修正）中皆已
`completed`——上面看到的損壞資料是**這次重抽的新結果**，不是舊快照。代表這個
變體目前正在即時汙染主 drain 剩餘 ~2850 個待處理 chunk 裡任何含類似級距表的文件，
不修就繼續累積，等全量跑完再回頭清理的成本會比範圍修飾詞（§2.1，目前查無其他
真實案例）高得多。

## 4. 設計

### 4.1 核心機制：範圍修飾詞雙向過濾

新增 `_SCOPE_MODIFIER_PATTERN`，比照 `_QUANTITY_PATTERN`／`_MEASURE_PATTERN`
既有架構（NegEx 式受控觸發詞表 + regex），但**不做早退**（與 `_MEASURE_PATTERN`
不同）——而是在比對迴圈**前**，把候選清單依「是否含範圍修飾詞」與 `name` 分成
同類/異類，只保留同類候選進入編輯距離／cosine 比對：

```python
_SCOPE_MODIFIER_PATTERN = re.compile(r"增加|額外|追加|新增")

def resolve_entity_name(name, candidates, ...):
    if _MEASURE_PATTERN.search(name):
        return name

    name_has_modifier = bool(_SCOPE_MODIFIER_PATTERN.search(name))
    candidates = [
        c for c in candidates
        if c["name"] == name
        or bool(_SCOPE_MODIFIER_PATTERN.search(c["name"])) == name_has_modifier
    ]
    # ↓ 以下編輯距離／cosine 兩個迴圈改用過濾後的 candidates，其餘邏輯不變
    ...
```

**為什麼不是早退，而是雙向過濾**：`_MEASURE_PATTERN` 命中就整個跳過模糊比對，
適合「這個名稱本身就是精確量詞、不該跟任何東西模糊合併」的情境。範圍修飾詞
不同——「每增加一種型式」若跟另一個同樣含「增加」的候選（例如未來語料裡
「每再增加一種型式」）比對，仍然**應該**走正常的模糊合併邏輯，只是不該跟
「不含範圍修飾詞」的候選（「每一型式」）合併。過濾候選清單（而非早退）能
保留「同類可模糊合併、異類不可比對」這個更精確的語意。

### 4.2 觸發詞清單（v1，保守）

`增加|額外|追加|新增`——只有「增加」有本次真實案例（`每增加一種型式`）確認，
其餘三個是同義的「附加規定」常見措辭（法規領域常見寫法），依domain知識預防性
納入，比照 `_MEASURE_PATTERN` 當初從 `_QUANTITY_PATTERN` 擴充時「先涵蓋確認
案例、再依域知識預留相近變體」的既有慣例。**刻意不做**更寬泛的清單（如「另」
「再」「又」單字），這些字在法規文本中極常見於非範圍修飾語境（「另定之」「再者」
「又稱」），誤判風險高於效益，留待真的遇到新案例再擴充。

### 4.3 數字比較詞守衛：`_RANGE_COMPARATOR_PATTERN`（早退式，比照 `_MEASURE_PATTERN`）

新增 `_RANGE_COMPARATOR_PATTERN`，抓「裸數字（無須接單位）緊鄰以上／以下／以內／
未滿／超過」：

```python
_RANGE_COMPARATOR_PATTERN = re.compile(
    r"[〇零一二三四五六七八九十百千萬0-9]+\s*(?:以上|以下|以內)"
    r"|(?:未滿|超過)\s*[〇零一二三四五六七八九十百千萬0-9]+"
)

def resolve_entity_name(name, candidates, ...):
    if _MEASURE_PATTERN.search(name) or _RANGE_COMPARATOR_PATTERN.search(name):
        return name
    ...
```

**為什麼是早退，不是像 §4.1 那樣雙向過濾**：`resolve_entity_name()` 對量詞類
實體既有的設計原則（見 §850-882 行註解，發現3）是「數量/金額實體只准精確比對，
不做模糊合併」——即使兩個量詞短語措辭不同但實際上是同一件事，也**寧可各自成為
獨立節點**（下游仍可個別檢索到），不可能為了合併圖的精簡度去冒「不同數值被誤判
同一實體」的風險。§2.4 的範圍表格是這個既有原則的直接延伸（「1以上未滿10」與
「100以上未滿1000」在語意上就是不同實體，不是同一件事的兩種寫法），適用跟
`_MEASURE_PATTERN` 相同的早退邏輯，而不是 §4.1 範圍修飾詞那種「同類可合併、
異類不可比對」的雙向過濾邏輯——範圍修飾詞的「有/無修飾詞」是二元語意旗標，
數字比較詞的「以上/以下/未滿」則是每個值都可能代表完全不同的真實世界範圍，
沒有「同類」這個中間地帶。

**觸發詞清單（v1）**：`以上|以下|以內` 接於數字之後、`未滿|超過` 接於數字之前——
覆蓋本次真實案例（`未滿`／`以上`）及法規常見的對稱寫法（`以下`／`超過`／`以內`）。
刻意不含「大於」「小於」「介於」等白話數學用語（法規條文查證慣用「以上」「以下」
「未滿」「超過」，未見前述白話用語），也不含「公斤」「小時」等已由 `_MEASURE_PATTERN`
單位清單涵蓋的既有案例——兩個守衛疊加使用（`or`），互不取代。

## 5. 風險與相容性

| 風險 | 緩解 |
|---|---|
