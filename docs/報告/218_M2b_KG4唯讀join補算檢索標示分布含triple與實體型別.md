## 2. 對回方式與成功率

- **Fact**：鍵 `(source_doc_id, source_svo_chunk_index, fact_text)`；索引 16,551 個不同鍵（Fact 16,826 筆，有重複鍵）。**對回成功率**：22,784 筆被檢索 Fact 中對到 22,639（99.4%）、**歧義 0**、**未對到 145**（全部集中於 `t2_k1_topk40` 系列，該批 run 當時的 Fact 文字後來有變動），其餘設定 0 筆未對到。
- **triple**：鍵與 `bfs.py` 一致（文件取邊最後一筆引用；文字＝`natural_text`，缺則 `subject verb object`）。**已保存 trace 的 triple `source_svo_chunk_index` 全為 None**（報告164 V3 之前的快照），所以改以 `(doc, text)` 對回，trace 有 chunk 索引時才再縮小。索引 14,011 個鍵。10,987 筆被檢索 triple 中對到 10,819（98.5%）、**歧義 22**（同 doc＋同文字但不同 chunk 且標示不一致，不計入、不猜）、**未對到 146**（同樣集中於 `t2_k1_topk40`）。
- **重複命中處理**：同鍵多筆時，標示全部一致則採用；不一致列「歧義」不計入分布。
- **實體型別**：Fact 以 `subject`／`object` 名稱對 `Entity.name`（KG#4 內 Entity 名稱唯一，實測 0 組重複名）；查無該名稱的 Entity 標為「無法對回Entity」（不猜型別；全圖 Fact 中 964 筆〔5.7%〕主詞名稱查無 Entity）。triple 的兩端本身是 Entity，必可取得型別。
- **限制**：①Fact 的「條號」取自 `SUPPORTED_BY→LawArticle`，「文件層適用條號」取自 Fact 全表（該文件任一 Fact 有條號即適用）；triple 取最後一筆引用的 `article_no`，文件層取自全部邊引用。②同一事實跨多個 stage／run 會重複計，下表為各設定內分布，「全部彙總」僅為合併規模、不可視為去重。③標示名稱／值域仍為 PROVISIONAL。

## 6. 描述性觀察（不作品質結論）

1. 被檢索 Fact 中「尚未處理」占比（19.9%–23.2%）低於全圖（30.5%）；**進 prompt 後又升高到 24.1%–26.7%**——被截斷／渲染過濾留下的集合比被檢索集合更偏向「空受詞但有 verb」類事實，而「未知」類被現行過濾完全排除（0 筆）。
2. triple 側殘缺比例（約 8%–11%）明顯低於 Fact 側（24%–27%）。
3. 關係型別來源不明（RELATED_TO）在 Fact 約 9 成、triple 約 8.5 成，檢索前後幾乎不變。
4. 條號在對回後幾乎全為「已解決」，與全圖一致。
