## 2. 重複次數規則（事先宣告，程式碼在 `scripts/eval/adaptive_repeat.py`）

使用者要求「依品質檢測，未達標才重複」。**達標** = 無錯誤／逾時、`is_perfect` 為真、且該題若有 scope audit 規則則須通過。逾時／錯誤的執行視為無效、不計入並補跑（最多 2 次）。序列式決策：第 1 次達標→暫記「單次通過」；未達標→補第 2 次；兩次一致即定案（穩定通過／穩定失敗）；不一致→補第 3 次裁決；最多 3 次。因為只重複失敗題會讓「運氣好的單次通過」不被發現，另以固定種子（`20260920`）從單次通過題抽約 25%（至少 4、最多 10）再跑一次，用來估計單次通過的可靠度。本次抽查名單固定為 `18-Q2`、`26-Q1`、`57-DIST1`、`57-DIST2`（`audit_sample.json`）。

## 4. 續跑步驟

1. **先騰出記憶體**：評測期間 Ollama 常駐約 9GB，先前被系統以記憶體不足中止 3 次（已完成的題目都保留，只損失進行中的那一題）。續跑前請確認可用記憶體至少約 8GB；先前停掉 `kg2-api`、`kg2-world` 兩個容器有幫助（已於暫停時重新啟動；續跑前可再 `docker stop kg2-api kg2-world`，評測結束後 `docker start` 還原），也可關閉 Antigravity IDE 等程式。評測期間請勿同時使用 Ollama。**使用者已授權：被記憶體中止時可直接自動接續。**
2. **算出還要跑哪些題**（規則已寫在程式裡，直接讀全部階段的紀錄）：
   **來源一致性（2026-09-21 決定）**：`stage_a3`、`stage_b` 當時的 Ollama 實例無法證明是 Windows 0.34.2，故**擱置不納入判定**（目錄保留供查證，`frozen_manifest.json` 的 `quarantined_stages` 有記錄），這 8 題改在標準實例重跑；`stage_a`、`stage_a2`（38 題）依中止時的 Windows 端行程判定為標準實例。判定時只讀標準來源的階段：
   ```
   F=data/eval/baseline_runs/20260920_frozen
   python scripts/eval/adaptive_repeat.py --bank data/eval/test_cases.json      --records A=$F/stage_a/records.json --records A2=$F/stage_a2/records.json      --records B3=$F/stage_b3/records.json      --eligible-ids $F/frozen_manifest.json --audit-file $F/audit_sample.json --seed 20260920      --summary-out $F/summary_latest.json --emit-questions $F/next_questions.json
   ```
   輸出的 `next_run_ids` 為空即完成。第一次判定（只讀 A、A2）得 34 題（`next_questions_b3.json`：26 題未達標補第 2 次、4 題抽查、4 題 AGGR16–19 首跑），其結果寫入 `stage_b3`；`stage_b3` 之後的階段再以新的 `--out` 接續。
3. **跑一個階段**（新的 `--out`，不可覆寫既有目錄）：
   ```
   export WORKSPACE_DIR=D:/Users/666/Desktop/kg-runtime NEO4J_URI=bolt://localhost:17990 NEO4J_PASSWORD=kg2_test_2026
   python scripts/eval/frozen_baseline_stage.py run --frozen-dir $F --questions $F/next_questions.json --out $F/stage_b3
   ```
   （`stage_b2` 目錄是誤連 WSL Ollama 的空跑，0 題完成，不納入。）
4. 把新階段的 `records.json` 加進第 2 步的 `--records` 清單，重複第 2–3 步，直到 `next_run_ids` 為空（`stage_b3` 之後預計只剩第 1、2 次結論不一致的題）。
