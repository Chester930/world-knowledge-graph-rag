## 4. B5：KG#4 備份程序書（只寫文件，未執行）

以下是依本次合成演練整理的程序草案。命令中的 `kg2-neo4j`、`kg2_neo4j_data` 與 production 路徑僅供日後逐項審閱；本次沒有執行任何一行，也沒有對 KG#4 做備份。

### 建議與前置條件

以可用性優先，建議日後先採用 A 的 Enterprise 線上 backup；在有維護窗口時另做 C 的冷備份作為保守副本。B 作為需離線但可搬移的替代方案。這個建議只根據合成資料演練：A 備份檔最小且備份期間 0 秒停機；C 的位元級檔案複製最保守但檔案較大；B 的 dump/load 易於理解但需離線。

執行前必須同時滿足：

1. 使用者逐項確認備份方法、停機窗口、輸出位置、保留份數、還原責任人與回退決策；確認無其他 writer、worker、n8n、Dify 或人工 session 連線。
2. 先以唯讀命令盤點狀態與空間；停止／drain worker 只能在使用者另行同意後做：

   ```powershell
   docker ps --format "{{.Names}}`t{{.Status}}"
   docker inspect --format '{{.State.Status}}|{{.State.StartedAt}}' kg2-neo4j
   docker system df -v
   # 另查 n8n／Dify／worker 的連線與佇列；確認 drain 完成後才進入備份窗口
   ```

3. 空間至少預留：目前 `kg2_neo4j_data` 唯讀彙總約 2.268 GB；保守規劃應能同時容納一份 C 級資料副本、一份還原工作區、A/B 產物與 20% 以上 headroom，即至少以約 3 倍目前資料使用量（約 6.8 GB）作起始檢查。這是容量規劃下限，不是本次 KG#4 實測；壓縮率與索引／交易檔分布可能使 A/B 明顯不同。
4. A 必須先確認 Neo4j backup service 已配置並可由容器內 backup port 使用；本機 help 明確寫明「backup service must have been configured beforehand」。

### A：線上 Enterprise backup（建議主路徑）

以下只是一份待批准程序，**未在 KG#4 執行過**：

```powershell
# 1. 先完成前置 drain、空間與 StartedAt 核對；確認 backup service 已配置
docker exec kg2-neo4j neo4j-admin database backup `
  --from=localhost:6362 `
  --to-path=/var/lib/neo4j/backups `
  --type=FULL neo4j

# 2. 將容器內檔案複製到 repo 外、受 ACL 保護的備份目錄；再記錄大小／SHA-256
docker cp kg2-neo4j:/var/lib/neo4j/backups D:\backup\kg2\A
Get-ChildItem D:\backup\kg2\A -Recurse -File | Get-FileHash -Algorithm SHA256
```

備份完成後先以 `neo4j-admin database backup --inspect-path` 或等價官方工具檢查檔案，再以獨立、空白且有足夠空間的 Neo4j 目標還原；不要直接覆寫唯一來源。還原前後比對節點／關係／索引 `ONLINE`、固定 KNN、production 檢索與寫入讀回。任何指紋不一致立即停下並保留來源與備份檔。

### B：離線 dump/load（替代路徑）

本機 help 明確要求 dump 時資料庫不能掛載在執行中的 Neo4j。日後若選 B，必須先取得停機批准、停止所有 writer，再依官方 5.26 程序讓 `kg2-neo4j` 完全停止，使用審批過的維護 helper 對 `kg2_neo4j_data` 執行：

```powershell
# 文件示意；尚未在 KG#4 執行，helper 名稱／掛載方式需使用者另行批准
neo4j-admin database dump neo4j --to-path=/var/lib/neo4j/dumps
neo4j-admin database load neo4j --from-path=/var/lib/neo4j/dumps --overwrite-destination=true
```

dump 檔先複製到外部備份位置、驗 hash，再在全新目標載入；不要把 `--overwrite-destination` 用在唯一來源上。演練中截半 dump 的 load 以非零碼失敗，因此失敗處置是保留原 dump、刪除失敗的還原工作區、重新建立全新目標，不在來源上重試。

### C：停止後 `/data` tar（冷備份替代路徑）

此法必須先停 `kg2-neo4j` 並確認沒有程序開啟 `kg2_neo4j_data`；用已批准、只掛載來源磁碟區與外部暫存目錄的 helper：

```powershell
# 文件示意；尚未在 KG#4 執行，helper 名稱、映像與掛載參數必須使用者逐項批准
docker run --name <approved-tar-helper> --memory 3g --user 0:0 `
  -v kg2_neo4j_data:/data:ro `
  -v D:\backup\kg2:/backup `
  --entrypoint tar neo4j:5.26-enterprise `
  -czf /backup/kg2-data.tar.gz -C /data .
Get-FileHash D:\backup\kg2\kg2-data.tar.gz -Algorithm SHA256
```

還原必須解到新的、經批准的目標磁碟區，再以全新容器啟動並完成同一組指紋／KNN／production 檢索／寫入讀回檢查。不得把來源磁碟區當作還原目標，也不得在證據不足時刪除來源。

### 明確限制與使用前警語

**以上 KG#4 程序尚未在 KG#4 上執行過，執行前必須使用者逐項同意。** 本次沒有 KG#4 備份檔；報告248不構成「KG#4 已有備份」的宣稱。合成資料檔案大小、壓縮率、停機時間與索引建置時間不能直接線性外推到實際 2.268GB KG#4。
