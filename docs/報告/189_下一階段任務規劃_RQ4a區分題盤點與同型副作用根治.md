## 3. 各任務規格

### D1：RQ4a 區分題盤點（唯讀 Neo4j）

**目標**：回答「RQ4a 若要有區分力，題庫（65 題）／凍結 42 題中，有多少題的答案路徑涉及**非 `RELATED_TO`** 的型別邊？」——若這類題極少，RQ4a 在現行題庫上沒有檢定力，不值得做；若有一批，才有「補題＋RQ4a」的基礎。
**防護（與報告185 C1 完全相同，缺一不可，違反即停止）**：

1. 開始前先 `ListAgents` 確認沒有其他 session 在用同一 Neo4j／Ollama；記錄結果。
2. 使用既有 `kg2-neo4j` 容器（KG#4 端點 `bolt://localhost:17990`）。**KG#4（`236903cf`）資料是唯一副本，絕對不得 wipe／清空／重建。**
3. **只執行唯讀 Cypher**（`MATCH … RETURN`），以 `default_access_mode=READ` 連線；沿用 C1 腳本的寫入關鍵字攔截。
4. **不啟動 Ollama／WSL 模型、不呼叫任何 LLM／embedding。**
5. 執行前後各查一次總節點／總關係／Fact／Entity 數（應為 57,451／137,873／16,826／12,296），**須相同**，寫入報告。
**做法**：

- 對題庫 65 題逐題：由題庫 `gold`／`atomic_gold_facts`／`source_article` 定位所涉文件與 chunk（沿用 C1／報告187 的定位法），查該 chunk 範圍內**與 gold 事實直接相關的邊**的 `rel_type`；分類為「全部 `RELATED_TO`」／「含非 `RELATED_TO` 型別邊」／「無法定位」。
- 輸出：每題一行（題號、題型、是否在凍結 42 題、verified 狀態、分類、非 `RELATED_TO` 邊的型別與數量、定位依據）；彙總表：各類題數、凍結 42 題內各類題數。
- **定位不確定就標「無法定位」，不要猜**；定位法與限制寫明（沿用 C1 的 chunk 範圍法會有粒度誤差，須說明）。
- 依彙總數字回答檢定力：若「含非 `RELATED_TO`」題在凍結內為 *k* 題，以報告179 §3 的檢定力表（所需不一致對 12／20／49）說明在 *k* 下是否可能顯著。**〔推論〕要標明。**
**驗收**：Cypher 逐條列出供我檢查唯讀；前後總數相同；每題分類附定位依據；彙總數字可由逐題表重算（我會重算）；題庫檔零變更；無 LLM 呼叫。
**禁止**：任何寫入；啟動 Ollama；重抽；改題庫；產 gold；判斷法規正確性。
**停止條件**：發現其他 session 使用同一 Neo4j／Ollama；前後總數不一致；任何一步需要寫入或 LLM。
