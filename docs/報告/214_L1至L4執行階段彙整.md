## 3. L1：「概念」實體抽樣

### 3.1 抽法與來源

母體是 `Entity.type` 精確等於「概念」的 8,023 個實體。固定種子為 `20261012`；候選先依名稱／type 字面排序，再以 `random.Random(20261012).sample(..., 50)` 無放回抽 50 個，最後依名稱／type 排序並編號。抽法、種子、母體數與樣本均寫入審閱檔及 raw JSON，可由 `scripts/analysis/concept_entity_sampling.py` 重算。

每筆列出名稱、事實邊入＋出度（自環計 2）及最多 12 條引用事實。樣本內共取得 90 條引用事實；49 筆實體的可列事實少於 12 條，按實際度數列出，沒有用人工資料補足。

原句取法沿用報告200：`source_sentence_start/end` 是 chunk 內相對範圍，不是原文全域句子索引；以 chunk、subject／verb 子字串錨點比對，並以 `original.md` 的逐字內容為來源。結果中 88 條引用命中 subject／verb 錨點，1 條僅能以 chunk 單句候選呈現，1 條（樣本第41筆）找不到唯一原句錨點；該筆保留 chunk 內逐字候選，並標為疑問，沒有捏造唯一原句。

### 3.2 草稿標準與結果

標註標準如下，全部是單人草稿、**未經使用者確認**：

* **P**：名稱有更合適的 schema.org 標準型別，並附建議型別，例如 Person、Organization、Place、Action、Legislation、QuantitativeValue 等。
* **C**：目前名稱與上下文較符合制度、規定、狀態、數量、行為等抽象概念，沒有明顯更合適的 schema.org 型別。
* **U**：現有名稱與最多 12 條上下文不足以判斷。

疑問旗標只表示執行者認為需要使用者看；疑問筆置於審閱檔最前面，沒有為了讓比例好看而硬標。樣本 50 筆的草稿統計如下：

| 草稿標註 | 筆數 | 比例 | Wilson 95% 區間 |
|---|---:|---:|---:|
| P | 31 | 62.0% | 48.15%–74.14% |
| C | 11 | 22.0% | 12.75%–35.24% |
| U | 8 | 16.0% | 8.34%–28.51% |
| 疑問旗標 | 12 | 24.0% | — |

Wilson 區間是樣本比例的不確定性描述，不是母體真值的保證；樣本只有 50 筆，且標註為單人草稿。這份抽樣不替使用者決定「概念」在整體標示中應採 A（視為未知）或 B（視為真的概念）；L3 仍將 A／B 並列。

可供審閱的逐筆材料與可重算輸入如下：

* [L1 審閱檔](214_L1概念實體抽樣審閱.md)：疑問筆在前；使用者可直接回覆「第 N 筆改成 X」。
* [L1 CSV](214_L1概念實體抽樣.csv)：包含名稱、度數、三元組、文件／chunk、原句、草稿標註、理由、疑問旗標與「草稿，未經使用者確認」狀態。
* [L1 raw JSON](214_L1概念實體抽樣_raw.json)、[草稿輸入](214_L1概念實體抽樣草稿標註輸入.json)、[草稿結果](214_L1概念實體抽樣草稿標註.json)、[統計](214_L1概念實體抽樣統計.json)。

### 3.3 限制與不確定處

L1 只提供一個固定種子、50 筆、單人草稿；P／C／U 與理由不是使用者裁示。第41筆缺少唯一錨定原句，審閱檔列出 chunk 內逐字候選並置疑問；其餘疑問主要是上下文不足、名稱同時混合多種語意或 verb 承載規則文字。每筆理由已隨名稱、三元組與所列上下文逐筆放在審閱檔；仍不把這個自我檢查當成使用者確認。

## 4. L3：Phase 0 基準線重算與覆蓋率

新增 `scripts/analysis/semantic_marks_coverage.py`，匯入不連線、不讀環境變數、不改 `os.environ`；只有 `main()` 建立 Neo4j driver，查詢交給既有唯讀 runner。測試包含純運算分支、匯入環境快照，以及與 Phase 0 JSON 的比較邏輯。

L3 對實體型別、關係型別、`source_article_no`、空欄位，在 strict／A／B 下重算；對照 `docs/報告/208_K2_phase0_raw結果.json` 的 16 個比較項目，輸出均為「一致」。這裡的「一致」是腳本輸出的逐項結果，不是把儲存層標示當成已存在。

### 4.1 Phase 0 基準線口徑

| 對象 | Phase 0 直接可判定／已解決 | Phase 0 需人工／來源不明等 | 備註 |
|---|---:|---:|---|
| 實體型別 | 4,273／12,296 = 34.75% | 8,023／12,296 = 65.25% | strict：標準型別 2,481；空 805；outside_raw 987；概念-only 8,023 |
| 關係型別 | 1,832／16,826 = 10.89% | 14,994／16,826 = 89.11% | `RELATED_TO` 是來源不明，不是由 verb embedding 有無推論 |
| `source_article_no` | 16,826／16,826 = 100% | 0 | 16,773 已知文件、53 不適用；不產生哨兵字串 |
| 空欄位（有任一空欄位的 5,281 筆） | 145／5,281 = 2.75% | 5,136／5,281 = 97.25% | 其餘完整 Fact 11,545 不列入這個分母 |

「概念」兩種算法必須並列：A 視為未知＝**8,828**；B 視為真的概念（已解決）＝**10,504**。987 是實體數，不是型別 token 種數；報告201 的 235 種是另一個口徑。

三個口徑差異明列如下：

1. 「其餘 4,619」只看空受詞且 verb 非空（4,597＋22）；本次「需人工」5,136 另外包含空主詞，或空 verb 但有受詞者。
2. 987 是實體數，不是型別 token 種數；235 種是報告201 的另一口徑。
3. 「概念」有 A／B 兩種算法：A 未知 8,828，B 已解決 10,504；本報告不替使用者選。

### 4.2 L3 兩種標示覆蓋率

| 對象 | concept scheme | 儲存層已有明確標示（甲） | 派生函式給出非「無法判定」標示（乙） | Phase 0 直接可判定參考 |
|---|---|---:|---:|---:|
| 實體型別 | strict | 0／12,296 = 0% | 4,273／12,296 = 34.75% | 34.75% |
| 實體型別 | A | 0% | 12,296／12,296 = 100% | 概念 A：8,828 為未知 |
| 實體型別 | B | 0% | 12,296／12,296 = 100% | 概念 B：10,504 為已解決 |
| 關係型別 | strict／A／B | 各 0% | 各 1,832／16,826 = 10.89% | 10.89% |
| `source_article_no` | strict／A／B | 各 0% | 各 16,826／16,826 = 100% | 100% |
| 空欄位（不完整 Fact） | strict／A／B | 各 0% | 各 5,281／5,281 = 100% | 直接可判定 145／5,281 = 2.75% |

乙欄是「查詢時可由函式產生某個值域結果」的覆蓋率；空欄位的 100% 包含 145 筆 `未知` 與 5,136 筆 `尚未處理`，不是 100% 已解決。甲欄是本階段不寫入資料的儲存層明確標示比例，預期為 0%；不能把乙欄說成已落地。

L3 還逐項對照空欄位組合：11,545／482／4,597／143／26／9／22／2，輸出與 Phase 0 JSON 一致。接手筆記所列兩個邊界也以唯讀資料查看：空字串 `rel_type` 為 0、`rel_type` 為 null 為 0、純空白 `article_no` 為 0；沒有因這兩點調整規則去湊數字。

## 5. L4：Phase 0 數字對下一步的意義

這些數字只說明目前資料在查詢時可被哪種派生函式描述，不等同於品質改善或落地決策：

* `source_article_no` 的 100% 可派生表示來源文件／不適用邊界已有完整輸入，若要接進檢索，主要是決定呈現與過濾語意，不是先補齊欄位資料。
* 關係型別只有 10.89% 可依現有 `rel_type` 判為已解決；14,994 筆 `RELATED_TO` 應維持「來源不明」的語意，不能從 `verb_embedding` 有無推導來源。
* 實體型別 strict 只有 34.75% 可依現有標準型別／原始字串規則直接判定；「概念」採 A 或 B 會使派生結果不同，L1 抽樣證據不足以替使用者決定。
* 空欄位的主要量體是 5,136 筆待人工／後續處理，而不是只有空受詞的 4,619 筆；接入回答前需要決定殘缺事實的呈現、排除或降權規則。
* L1 的 P／C／U 只能作為人工審閱材料；50 筆樣本的區間很寬，不能直接外推成 schema.org 改寫規則。

若要把派生結果接進系統，以下只列可能碰到的位置，不在本階段實作：

1. 查詢層組裝 Entity／Fact 結果時，附帶暫時標示與 `concept_scheme` 選項。
2. 關係過濾或排序時，明確處理 `RELATED_TO`「來源不明」，避免當成已解析關係。
3. 來源引用組裝時，使用既有 citation／文件識別，不新增 `source_article_no` 儲存欄位或哨兵值。
4. 回答生成的事實清單與提示上下文，決定如何顯示 `未知`、`尚未處理`、`不適用` 及殘缺欄位。
5. 若要落地標示，需另行設計 schema、回填／遷移、回退與測試，不由本階段代決。

待使用者裁示：

* 「概念」整體呈現是否採 A、B，或繼續保留可逆參數。
* P／C／U 草稿中哪些筆要改標；疑問旗標是否解除。
* 派生標示的欄位名、值域與是否日後落地儲存。
* `RELATED_TO` 來源不明在檢索／回答中要如何排序或呈現。
* 5,136 筆空欄位待處理資料的下游策略，以及是否需要後續人工標註。

## 6. 與報告212的差異、環境限制與未決事項

* 報告212要求每個實體附最多 12 條事實；本次依使用者目前指示執行，樣本內共 90 條，資料不足者照實少列。這不是把缺少的事實當成零。
* L1 的 `20261012`、50 筆、最多 12 條與疑問排序已固定寫入產物；不與報告210 的空受詞抽樣混用。
* L3 對 Phase 0 的比較結果均為一致；差異只在覆蓋率的語意呈現：派生函式對每筆輸出值域結果，不代表儲存層已有標示；空欄位的乙欄 100% 也不代表 100% 已解決。
* 本機工作樹的 `.env` 位置可用於執行，但先前指定的上層 `kg-reextract/.env` 路徑不在此工作樹可見位置；本次沒有輸出密碼、沒有把密碼寫入任何產物。這是執行環境路徑上的不確定處。
* 無法用 ListAgents 獨立查看 peer session；「Neo4j／Ollama 沒有他人使用」以使用者明確確認為依據。
* 所有 L1 標註與理由仍是單人草稿、未經使用者確認；L3 是唯讀派生計算，不是資料回填。
