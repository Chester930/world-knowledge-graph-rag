## 1. 總結

### 1.1 盤點範圍

- **SM-1 文件抽取狀態**：`DocumentRecord.extraction_status` 的五值域為 `pending`、`processing`、`completed`、`failed`、`pending_upload`，欄位定義在 `models/knowledge_graph.py:106-113`。
- **SM-1b 標準化前處理**：`DocumentRecord.normalization_status` 的四值域為 `not_started`、`processing`、`completed`、`failed`，定義在 `models/knowledge_graph.py:124-128`；它與 SM-1 分開保存。
- **SM-2 任務佇列**：`task_queue.status` 的五值域由 `services/task_queue_service.py:30-41` 定義／建立，SQLite 是效能索引，不是記錄檔的真實狀態來源。

SM-1 的 production 寫入路徑是初始化預設值、`reset_extraction_progress()`、`record_chunk_completed()`、`mark_extraction_failed()`、`append_assignment()`；SM-1b 有初始化重設與 `update_normalization_progress()`，但後者在 production 沒有呼叫者；SM-2 的 SQL 寫入集中在 `enqueue()`、`update_status()`、`claim_next_pending()`、`reset_stuck_processing()`、`_reconcile_doc()` 五個路徑，worker／重啟流程是其呼叫端。

### 1.3 重要現況

1. `_record.json` 是抽取狀態的真實來源；`task_queue.db` 是可由記錄檔重建的效能索引。成功尾段目前是 queue `processing → pending_upload`、記錄檔更新、queue `pending_upload → completed`，見 `services/extraction_worker.py:151-163`。
2. `record_chunk_completed()` 已用 `completed_chunk_indices` 集合判斷是否全數完成，但仍不看原本的 `extraction_status`；所以 X1 仍然成立。
3. `update_status()` 是刻意的低階無守衛寫入器；因此目前不只正常 worker 序列，連 `completed → processing`、`failed → completed`、`pending → completed` 這類非法轉移也會被接受。P1 若改成 `transition()`，必須先把這些現況列入特性測試與轉移表，不能直接套理想狀態機。

### 5.2 P1 必須容許的「不合理」轉移

若 P1 的唯一目標是「整理前後行為完全不變」，轉移表至少必須保留：

1. **SM-1 `failed → processing`**：`mark_extraction_failed()` 後另一 chunk 完成且集合未達 total，這是 X1 離線重現的既有結果（`services/document_record_service.py:205-214`）。同一低階 API 在完成集合已涵蓋 total 時也可得到 `failed → completed`。
2. **SM-1 任意 current → `pending`**：`reset_extraction_progress()` 與 `append_assignment()` 都直接寫 pending；不能只允許 `processing → pending`。
3. **SM-1b 任意 current → 任一傳入的四值**：雖然目前沒有 production caller，API 本身沒有 old-state guard（`services/document_record_service.py:149-160`）。
4. **SM-2 `completed → pending`、`failed → pending`**：再次 `enqueue()` 的終態 UPSERT；這不是一般 worker retry，而是既定重建／重排語意。
5. **SM-2 `update_status()` 任意 current → 任一合法 target**：至少要把 `completed → processing`、`failed → completed`、`pending → completed` 的實測結果鎖定，不能在 P1 重構時默默收窄。
6. **SM-2 `processing → pending`**：重啟 reset；並保留 reconcile 的「既有 failed 不自動重試」與 rebuild 的「清空後依記錄檔重登」不對稱。

### 5.3 P1 切分選項（不在本報告下最終決定）

| 選項 | 內容 | 主要風險 |
|---|---|---|
| A | 先 SM-2：把 queue 的 raw write、claim、reset、reconcile policy 以特性測試鎖定，再處理 SM-1 SSOT 回寫。 | worker 仍跨兩個未統一的狀態入口；若先改 queue 而未鎖定 worker 與記錄檔順序，可能改變重啟／中斷行為。 |
| B | 先 SM-1：集中記錄檔 reset／完成／失敗／重新歸屬，再接 worker 成功／失敗順序。 | X1 與 X3 都在 SSOT 邊界；若 transition API 同時修正語意，容易把「整理」與「修 bug」混在一個 diff。 |
| C | 先只新增 Enum／事件名稱／characterization tests，不替換任何 writer；通過後分兩個小批次接 SM-2、SM-1。 | 短期仍有多個寫入入口；需嚴格避免測試只驗新 API 而沒有鎖現有舊入口。 |

"""Offline characterization for report 119.

This script only exercises document_record_service and task_queue_service against
fresh temporary folders/SQLite files.  It never connects to Neo4j, Ollama, or a
server.  Usage:

    python reproduce_status_machines.py "D:/path/to/repo"
"""
from __future__ import annotations

import json
import sqlite3
import sys
from pathlib import Path
from uuid import uuid4


def main(repo: Path) -> None:
    sys.path.insert(0, str(repo))

    from services import document_record_service as records
    from services import task_queue_service as queue
    from services.ingestion_service import chunk_and_stage

    root = Path(__file__).parent / f"run-data-{uuid4().hex[:8]}"
    root.mkdir(parents=True, exist_ok=True)

    def state(folder: Path) -> dict[str, object] | None:
        record = records.read_record(folder)
        if record is None:
            return None
        return {
            "extraction_status": record.extraction_status,
            "normalization_status": record.normalization_status,
            "chunk_progress": record.chunk_progress,
            "completed_chunk_indices": list(record.completed_chunk_indices),
            "svo_total_chunks": record.svo_total_chunks,
        }

    def stage(name: str, source: str) -> Path:
        folder, _ = chunk_and_stage(
            "第一句。第二句。第三句。",
            source,
            root / name,
        )
        return folder

    def row(db_path: Path, chunk_index: int) -> str | None:
        with sqlite3.connect(db_path) as conn:
            found = conn.execute(
                "SELECT status FROM task_queue "
                "WHERE kg_id=? AND source=? AND chunk_index=?",
                ("kg-offline", "doc.md", chunk_index),
            ).fetchone()
        return found[0] if found else None

    output: dict[str, object] = {
        "repo": str(repo),
        "external_services": {"neo4j": False, "ollama": False, "server": False},
        "sm1": {},
        "sm2": {},
    }

    # SM-1 A: initial/assignment then one of three chunks completes.
    folder_a = stage("sm1-a", "a.md")
    records.append_assignment(folder_a, uuid4(), "offline", "manual")
    records.set_svo_chunk_total(folder_a, 3)
    records.record_chunk_completed(folder_a, 1)
    output["sm1"]["A"] = state(folder_a)

    # SM-1 B/X1: failure followed by a different chunk completion.
    folder_b = stage("sm1-b", "b.md")
    records.set_svo_chunk_total(folder_b, 3)
    records.mark_extraction_failed(folder_b)
    before_b = state(folder_b)
    records.record_chunk_completed(folder_b, 2)
    output["sm1"]["B_X1"] = {"before": before_b, "after": state(folder_b)}

    # SM-1 C: all chunks complete, then explicit reset.
    folder_c = stage("sm1-c", "c.md")
    records.set_svo_chunk_total(folder_c, 3)
    states_c = []
    for index in (1, 2, 3):
        records.record_chunk_completed(folder_c, index)
        states_c.append(state(folder_c))
    records.reset_extraction_progress(folder_c)
    output["sm1"]["C"] = {"after_each_chunk": states_c, "after_reset": state(folder_c)}

    # SM-1 D/X3: missing record write calls return None without raising.
    missing = root / "missing-record-folder"
    output["sm1"]["D_X3_missing_record"] = {}
    for label, call in (
        ("record_chunk_completed", lambda: records.record_chunk_completed(missing, 1)),
        ("mark_extraction_failed", lambda: records.mark_extraction_failed(missing)),
        ("set_svo_chunk_total", lambda: records.set_svo_chunk_total(missing, 3)),
        (
            "update_normalization_progress",
            lambda: records.update_normalization_progress(
                missing, status="processing", progress=1, total_sentences=2,
            ),
        ),
    ):
        try:
            result = call()
            output["sm1"]["D_X3_missing_record"][label] = {
                "return": None if result is None else "record",
                "raised": None,
            }
        except Exception as exc:  # pragma: no cover - characterization output
            output["sm1"]["D_X3_missing_record"][label] = {
                "return": None,
                "raised": f"{type(exc).__name__}: {exc}",
            }

    # SM-1 E: reassignment resets even a completed record to pending.
    folder_e = stage("sm1-e", "e.md")
    records.set_svo_chunk_total(folder_e, 1)
    records.record_chunk_completed(folder_e, 1)
    completed_e = state(folder_e)
    records.append_assignment(folder_e, uuid4(), "offline-again", "manual")
    output["sm1"]["E"] = {"before_assignment": completed_e, "after_assignment": state(folder_e)}

    # SM-2 normal worker sequence.
    db_path = root / "queue.db"
    queue.enqueue(db_path, "kg-offline", "doc.md", [1])
    sequence = [{"event": "enqueue", "status": row(db_path, 1)}]
    sequence.append({"event": "claim_next_pending", "result": queue.claim_next_pending(db_path), "status": row(db_path, 1)})
    queue.update_status(db_path, "kg-offline", "doc.md", 1, "pending_upload")
    sequence.append({"event": "update_status(pending_upload)", "status": row(db_path, 1)})
    queue.update_status(db_path, "kg-offline", "doc.md", 1, "completed")
    sequence.append({"event": "update_status(completed)", "status": row(db_path, 1)})
    output["sm2"]["normal_sequence"] = sequence

    # SM-2 enqueue UPSERT behavior for terminal versus in-flight statuses.
    for index, status in ((2, "completed"), (3, "failed"), (4, "processing"), (5, "pending_upload")):
        queue.enqueue(db_path, "kg-offline", "doc.md", [index])
        queue.update_status(db_path, "kg-offline", "doc.md", index, status)
    before_reenqueue = {str(i): row(db_path, i) for i in range(2, 6)}
    queue.enqueue(db_path, "kg-offline", "doc.md", [2, 3, 4, 5])
    output["sm2"]["enqueue_again"] = {
        "before": before_reenqueue,
        "after": {str(i): row(db_path, i) for i in range(2, 6)},
    }

    # SM-2 reset_stuck_processing changes only processing (isolated DB).
    reset_db = root / "reset.db"
    for index, status in ((10, "pending"), (11, "processing"), (12, "completed"), (13, "failed"), (14, "pending_upload")):
        queue.enqueue(reset_db, "kg-offline", "doc.md", [index])
        queue.update_status(reset_db, "kg-offline", "doc.md", index, status)
    affected = queue.reset_stuck_processing(reset_db)
    output["sm2"]["reset_stuck_processing"] = {
        "affected": affected,
        "after": {str(i): row(reset_db, i) for i in range(10, 15)},
    }

    # SM-2 X3: missing row update is a silent no-op.
    missing_before = row(db_path, 999)
    try:
        missing_return = queue.update_status(db_path, "kg-offline", "doc.md", 999, "completed")
        missing_error = None
    except Exception as exc:  # pragma: no cover - characterization output
        missing_return = None
        missing_error = f"{type(exc).__name__}: {exc}"
    output["sm2"]["X3_missing_row_update"] = {
        "before": missing_before,
        "return": missing_return,
        "after": row(db_path, 999),
        "raised": missing_error,
    }

    # SM-2 deliberately illegal transitions are accepted by update_status.
    illegal = {}
    for index, initial, target in (
        (20, "completed", "processing"),
        (21, "failed", "completed"),
        (22, "pending", "completed"),
    ):
        queue.enqueue(db_path, "kg-offline", "doc.md", [index])
        queue.update_status(db_path, "kg-offline", "doc.md", index, initial)
        queue.update_status(db_path, "kg-offline", "doc.md", index, target)
        illegal[f"{initial}->{target}"] = row(db_path, index)
    output["sm2"]["illegal_update_status"] = illegal

    # SM-2 restart/reconciliation behavior in a fresh DB, using only the record file.
    reconcile_root = root / "reconcile-kg"
    reconcile_doc = stage("reconcile-staging", "reconcile.md")
    reconcile_root.mkdir(parents=True, exist_ok=True)
    kg_doc = reconcile_root / reconcile_doc.name
    kg_doc.mkdir(parents=True, exist_ok=True)
    for child in reconcile_doc.iterdir():
        if child.is_file():
            (kg_doc / child.name).write_bytes(child.read_bytes())
    records.set_svo_chunk_total(kg_doc, 3)
    records.record_chunk_completed(kg_doc, 1)
    rebuild_db = root / "rebuild.db"
    queue.rebuild_from_records(rebuild_db, {"kg-offline": reconcile_root})
    with sqlite3.connect(rebuild_db) as conn:
        rebuilt = conn.execute(
            "SELECT chunk_index, status FROM task_queue ORDER BY chunk_index"
        ).fetchall()
    output["sm2"]["rebuild_from_records"] = rebuilt

    print(json.dumps(output, ensure_ascii=False, indent=2, default=str))


if __name__ == "__main__":
    if len(sys.argv) != 2:
        raise SystemExit("usage: reproduce_status_machines.py REPO_ROOT")
    main(Path(sys.argv[1]).resolve())
