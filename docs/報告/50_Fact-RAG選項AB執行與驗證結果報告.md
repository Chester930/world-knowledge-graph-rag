### 2.2 對 KG#4 執行 backfill 的過程（連續三次失敗才成功）

1. **第一次**：`run_in_background` 任務被系統判定記憶體不足直接砍掉，無進度輸出。
2. **第二次**（加分批進度輸出）：跑到 `skip=3600`（21.5%）時 `httpx.ReadError`（Ollama 連線中斷）拋出未捕捉例外。⚠️ 因 Bash 指令 `python ... | grep -v ...` 沒開 `pipefail`，`grep` 的結束碼蓋掉了 Python 的非零結束碼，一度誤判為「成功」。
3. **第三次**（加 `start_skip` 接續＋單筆 `encode()` 失敗重試）：從 `skip=3600` 接續，跑到 `skip=6000`（35.8%）又被系統記憶體不足砍掉。
4. **根因診斷**：`Get-Process` 查出 `vmmemWSL`（WSL2 虛擬機）佔用 11.3GB，是全機器最大記憶體消耗者；單獨重啟 WSL2 內的 Ollama 服務（`systemctl restart ollama`）無法回收這個配額（僅 2.8GB→3.6GB），只有完整 `wsl --shutdown` 才有效，但會中斷所有 session 共用的 Neo4j/Ollama。使用者裁示先暫停、記錄現況。
5. **等待期間**：記憶體自然回升至 ~9.5GB 可用（推測是 WSL2 VM 閒置一段時間後的自然行為，或其他 session 的負載結束）。使用者核准重試。
6. **第四次（成功）**：從 `skip=6000` 接續，全程 0 次重試觸發，耗時 7095.7 秒（約 118 分鐘），更新 10736 條 Fact，`skip` 到達 16736（總數），完整跑完。**KG#4 現在是一致狀態**：全部 16736 條 Fact 的 `fact_embedding` 皆已套用文件代碼前綴。

**教訓**（已記入 memory）：① 背景執行的管線務必 `set -o pipefail`；② WSL2 VM 記憶體只會漲不會自動還，長時間高負載任務前應該先檢查 `vmmemWSL`；③ 中斷後不要盲目整個重跑，先確認上次進度、用 resume 機制接續。

## 4. 選項A（hybrid dense+fulltext RRF）驗證結果

### 4.1 程式碼

`services/svo_service.py::vector_search_facts()` 新增 keyword-only `question`／`hybrid`（預設 `False`，零行為變化）。`hybrid=True` 時對 `Fact.fact_text` 額外跑一趟 Neo4j fulltext 查詢（cjk analyzer，近似 BM25），與既有 dense cosine 候選池用 RRF（Cormack et al. 2009）融合。fulltext 索引不支援時優雅退回純 dense。11 個測試，pytest 906 全綠（peer session `b6d2585`，prototype 階段完成，未接線進 `chat()`，也未對真實 KG 驗證過——本報告是首次真實驗證）。

### 4.2 對 26-Q5 的實測（在已套用選項B 的 KG#4 上）

用 `vector_search_facts(driver, kg_id, question_vector, top_k=20, question=Q5文字, hybrid=True)` 直接對比 `hybrid=False`：

- **dense-only top20**：3 條來自 N0050030（目標文件），但都不含「當月一日」。
- **hybrid=True top20**：同樣 3 條來自 N0050030（RRF 讓其中一條排名前移），但**依然不含「當月一日」**。

**目標事實在 hybrid 模式下仍未進入 top20。**

### 4.3 為什麼兩種機制都失效——比報告43 §1 診斷更深一層的根因

問句原文：「災區受災勞工，符合規定者在災後多久的期間內，個人應負擔的保險費由中央政府支應？**這個期間從哪一天開始起算？**」

目標事實：「**災害發生之當月一日起** 計算 前條所定災後六個月期間」

**問句本身沒有出現「當月一日」「災害發生」這些目標事實的關鍵內容詞**——問句用的是「期間」「起算」「哪一天」這種**每一條雜訊事實（其他7部法規的「起算」樣板）都同樣會命中**的泛用詞彙。

- **Dense（語意相似度）失效原因**：目標事實與雜訊事實在「起算」這個語意主題上高度相似，問句的語意向量對兩者的區分力不足（報告41 §9 已診斷）。
- **Sparse（fulltext/BM25）失效原因（本報告新增診斷）**：BM25／fulltext 靠「問句與文件的詞面重疊」評分，但問句根本沒提到「當月一日」——真正有鑑別力的內容詞只存在於目標事實本身，問句與目標事實之間的詞面重疊反而**不比**問句與雜訊事實的重疊多（雙方都共享「起算」「期間」等泛用詞）。BM25 的 IDF 機制對這種情境幫不上忙，因為問題不是「目標事實用了罕見詞但没被抓到」，而是「問句本身沒有問出任何能指向目標事實的獨特線索」。

**這代表 26-Q5 需要的不是更好的排序演算法，而是不同層次的檢索邏輯**——例如「先鎖定回答第一子問題（六個月期間）的文件，再對同一份文件內的其他事實做第二輪檢索」這種**文件範圍內的多跳/二次檢索**，精神上類似 L9 V1 對 BFS 做的「錨定優先」，但那是解決「文件範圍」問題、不是「同文件內哪條事實」問題，目前系統沒有對應機制。屬於一個新的、更大的設計課題，不是本報告選項A/B 的範圍能涵蓋。
