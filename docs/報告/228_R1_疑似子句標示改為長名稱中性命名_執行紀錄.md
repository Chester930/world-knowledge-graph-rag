# 報告228：R1——「疑似子句」標示改為中性名稱（只改名稱，不改規則）

> **日期**：2026-10-01　**依據**：報告227（規劃對話指定新名稱；使用者「同意建議，先處理疑似子句改名」）　**性質**：純改名＋校準資訊註解；**規則、門檻、關鍵字、判定邏輯、兩級分級、trace 鍵名、旗標行為全部不變**。未連 Neo4j、未啟動 Ollama、未動 routers／core。

## 1. 為什麼改名

`mark_entity_name_shape()` 是**字面規則**（長度 ≥12＋條文用語等特徵）。報告223 的「強候選」占全圖 ≥12 字名稱的 **89%**（4,676／5,227），但報告226 §5c 的 O2 盲測複核（50 筆、雙獨立標註員，含使用者對 2 筆的確認；樣本小、區間寬、屬模型複核）顯示：含謂語的**子句 54%**（27／50）、無謂語**名詞片語 44%**（22／50）、專有名詞 2%（1／50）。叫「疑似子句」會讓人把標示數量當成子句數，故改為只描述字面現象的「長名稱」。

## 2. 改名對照表（規劃對話指定，未自行更換）

| 項目 | 舊 | 新 |
| --- | --- | --- |
| 值：長度＋特徵 | `疑似子句（長度＋特徵）` | `長名稱（含條文用語）` |
| 值：僅長度 | `疑似子句（僅長度）` | `長名稱（僅長度）` |
| 值：未達門檻 | `非子句` | `非長名稱` |
| 值：空／None／非字串 | `無法判定` | `無法判定`（不變） |
| 常數 | `NAME_SHAPE_CLAUSE_STRONG` | `NAME_SHAPE_LONG_STRONG` |
| 常數 | `NAME_SHAPE_CLAUSE_LENGTH_ONLY` | `NAME_SHAPE_LONG_LENGTH_ONLY` |
| 常數 | `NAME_SHAPE_NOT_CLAUSE` | `NAME_SHAPE_NOT_LONG` |
| 函式 | `is_suspected_clause_shape()` | `is_long_name_shape()` |

不變：`mark_entity_name_shape()`、`name_shape_features()`、`NAME_SHAPES`、`NAME_SHAPE_INDETERMINATE`、`NAME_SHAPE_DEFAULT_THRESHOLD`、`NAME_SHAPE_KEYWORDS`、trace 鍵 `subject_name_shape`／`object_name_shape`。**不保留舊別名。**
