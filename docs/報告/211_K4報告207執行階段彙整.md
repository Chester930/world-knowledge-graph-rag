## 5. Phase 0 數字對 Phase 1 決定的意義

### 5.1 可以先用查詢時派生的對象

- **`source_article_no`**：16,826 筆引用可依文件層有無條號唯讀分成已知 16,773／不適用 53／未知 0。若使用者只需要查詢與報表層語意，這個對象已有完整的 Phase 0 派生路徑；若之後落地欄位，報告201 建議使用獨立 scope 屬性，不要以 `N/A`／`UNKNOWN` 哨兵字串填入 `article_no`，因現有 `if article_no:` 路徑會把哨兵當真條號。
- **實體型別的一部分**：標準型別、空值、非標準原字串可由現有值分類；但 8,023 個「概念」無法只靠資料決定是未知或真概念，因此不能把「約 100% 可分類」誤寫成「約 100% 已解決」。
- **關係型別的一部分**：非 `RELATED_TO` 的 1,832 Fact 可報為已解決；其餘 14,994 的來源不可由現有圖譜反推。`verb_embedding` 不能代替來源標示。

### 5.2 必須先取得人工／LLM 判讀的對象

- **空欄位**：至少一空的 5,281 個 Fact 中，只有空受詞且空 `verb` 的 145 筆被目前操作型規則單獨分出；其餘 5,136 仍混合「原句沒有受詞」「受詞被併入 verb」「欄位錯置／無法判斷」。K3 的 70 筆材料把人工確認成本縮成可逐筆回覆，但尚未產生使用者確認結果。
- **「概念」**：A/B 兩算法差 8,023 筆，這不是統計誤差，而是欄位語意與表示法的使用者決定；Phase 1 不應先回填其中一種。
- **`RELATED_TO` 來源**：89.11% 的 Fact 在嚴格口徑下來源不明；若要拆成刻意一般關聯、缺失、詞彙外退回、仲裁降級，需要抽取／仲裁流程留下 provenance，不能用現有欄位猜回去。

### 5.3 因此 Phase 1 的順序資訊

這些數字支持「先決定語意與狀態表示法，再選擇哪些欄位落地」的順序：`source_article_no` 最容易先做查詢時派生；型別與關係需要先處理含混來源；空欄位需要使用者審閱 K3 草稿，再決定是否引入抽取端明示旗標或 Fact／邊狀態欄位。這是執行結果對工作順序的意義，不是替使用者選定設計。
