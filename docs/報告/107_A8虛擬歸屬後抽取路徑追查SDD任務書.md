## 0. 背景與假設

`services/classify_service.py::assign_document_to_kg()` 在預設（`ENABLE_VIRTUAL_MANIFEST_ASSIGN=True`）下**不搬移文件**，只更新 KG 資料夾內的 `_members.json`，並回傳**原本的文件資料夾**（中央文件池／暫存區路徑）。之後 `routers/staging.py` 把這個回傳值傳給 `services/svo_service.py::trigger_extraction(driver, doc_folder, kg_id)`。

Claude Code 閱讀程式碼後提出一個**待驗證的假設**（不保證成立）：

> `trigger_extraction()` 以 `kg_folder = doc_folder.parent` 當作「KG 資料夾」，並把 SVO 切塊（`svo_index.json`）寫到 `document_folder_path(source, kg_folder)`；但背景 worker（`services/extraction_worker.py::_process_one` → `_find_chunk`）是到 `Path(kg.folder_path)` 底下找同一份檔案。虛擬歸屬模式下，前者是暫存區／中央池，後者是 KG 自己的資料夾（只有 `_members.json`）——兩邊可能對不上，worker 會回報「找不到 SVO chunk」而把任務標成 `failed`。

KG#4 是由匯入腳本建立（直接傳 `articles=`，路徑是另一條），不受影響；本任務只關心**產品的網頁上傳→分類→抽取這條路**。

## 2. 步驟

### S1　純閱讀

### S2　暫存目錄重現（不碰 Neo4j）

在**系統暫存目錄**（例如 `$env:TEMP\a8_repro`，不要放進 repo）建立重現腳本，步驟：

1. 建立暫存的 `staging/` 與 `kg_folder/` 兩個資料夾；
2. 用 `services/ingestion_service.py::chunk_and_stage(text, source, staging_dir)` 把一段簡短中文文字（例如 3–5 個句子）寫進 `staging/` 產生文件資料夾（`text` 用 ASCII 之外的一般中文句子即可，`source` 用 `a8_demo.txt`）；
3. 建 `KGInfo`（`services.classify_service.KGInfo`）指向 `kg_folder/`，呼叫 `assign_document_to_kg(doc_folder, kg_info, "manual")`（預設虛擬模式），記錄回傳路徑與 `kg_folder/` 內容（應只有 `_members.json`）；
4. 以 `unittest.mock`／`monkeypatch` 準備 `trigger_extraction` 所需依賴：`KGRepository(driver).get` 回傳一個具 `pronoun_lexicon_exclude=[]` 與 `folder_path=kg_folder` 屬性的簡單物件；`get_embedding_provider`／`get_llm_provider` 令其拋出 `RuntimeError`（此時函式會優雅降級）；`task_queue_service.enqueue`、`document_record_service.set_svo_chunk_total` 可 mock；`task_queue_db_path` 指向暫存檔；
5. 呼叫 `await trigger_extraction(fake_driver, <assign 回傳的路徑>, kg_id)`；
6. 檢查並列出：`staging/` 下與 `kg_folder/` 下各自出現了哪些檔案（是否有 `svo_index.json`、在哪個資料夾）；
7. 呼叫 `services.extraction_worker._find_chunk(kg_folder, "a8_demo.txt", 1)`，記錄回傳是否為 `None`。

**自我檢查**：
1. 步驟 3 之後 `kg_folder/` 應只有 `_members.json`（若不是，記錄實際內容，這本身就是發現）。
2. 若腳本因缺少依賴無法執行，寫下具體錯誤與你嘗試的修正，**不要為了讓它跑通而修改 repo 內任何檔案**；可改為只完成 S1 並在成果報告說明「重現未完成」的原因。
