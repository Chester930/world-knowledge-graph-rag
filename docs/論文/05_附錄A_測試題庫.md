本附錄使用兩組互補的標籤：**複雜度標籤**（§A.3.1，本題庫建立之初即有，供人工判讀與分層報告）與**場景類型** `scenario_type`（§A.3.2，2026-09-14 新增，供下游自適應行為樹動態路由與 Pareto 邊界分析使用）——後者不是前者的替代，是為了不同下游消費端新增的第二套視角。

### A.3.1 複雜度標籤定義

| 標籤 | 定義 | 例 |
|---|---|---|
| **單事實** | 答案是單一條文的單一數值／條件，取回一條事實即可作答 | 17-Q1 婚假 8 日 |
| **多事實組裝** | 需同時取回並分點列出多個同型（數字＋期限／金額＋條件）子事實，容易混淆或漏項 | 25-Q7 四項費用、26-Q3 四個期限 |
| **多跳／區間推理** | 需連接兩個以上事實，或做區間比對／條件套用才能得到答案 | 26-Q8 值→區間→係數；17-Q6 條件→天數 |
| **誠實拒答** | 原文無此規定，正解為「資料未明確記載」；用來驗證系統不臆測 | 26-Q7 |
| **陷阱（常識易錯）** | 一般常識傾向答錯、須以法條為準；與其他標籤並存 | 18-Q4 稅務比例、18-Q5 非年資 |

複雜度標籤同時供第五章 §5.6.1（B2 複雜度路由驗證）與 §5.5（分層報告答對率）使用。

### A.3.2 場景梯度標籤（`scenario_type`，引導行為樹路由）

為了引導下游「自適應行為樹（Behavior Tree）檢索路由」（03 §3.2 §d）並客觀評估各檢索架構的適用邊界，題庫除 §A.3.1 固有複雜度外，擴充 5 類問題場景標籤：

| 場景類型（`scenario_type`） | 定義與檢索特徵 | 預期最優路徑 | 範例 |
|---|---|---|---|
| **Type-A: `local_fact`**（單文局部事實） | 答案位於單一條文內，字面與語法連貫，無需跨條推理 | M1 (Naive Chunk) / M2 (Hybrid) | 17-Q1 婚假 8 日、18-Q4 召集假 150% |
| **Type-B: `dense_numerical`**（數值密集與但書） | 包含多個數值、期限、工資折半門檻或例外但書，容易漏項或被模型保守改寫 | M2 (Hybrid) / M3 (Fact-Vector) | 18-Q1 傷病假未住院/住院天數上限與折半 |
| **Type-C: `cross_document`**（跨文件多跳關聯） | 正確作答必須串聯兩部以上不同法規，純文字檢索常因詞彙差異產生檢索斷鏈 | M4 (Full-Graph BFS) | 災區受災傷病與職災給付抵充順序 |
| **Type-D: `global_aggregation`**（全域拓撲聚合） | 涉及全局性條件篩選或反向列舉（「有哪些法規規定…」），文字 Top-K 無法窮舉 | M4 (Full-Graph Cypher / 圖遍歷) | 統計需於 30 日內報備之法規與期限全集 |
| **Type-E: `canary_refusal`**（邊界誠實拒答） | 原文完全未規定該事項（金絲雀題型），用於檢驗模型是否具備邊界認知而非產生幻覺 | 全部方法（正解為「資料未記載」） | 26-Q7 高溫作業特殊健檢頻率（法規未定）；`canary-P1`／`canary-P4` |

> ⚠️ **實作狀態**：`QueryClassifier`（`services/query_classifier.py`）已實作 Type-A~E 分類邏輯並通過單元測試，但 Type-C（跨法規多跳）的判斷規則目前是題庫特定題目主題字串的硬編碼，屬於對已知題庫的過擬合、非可泛化分類器，正式接線前需重新設計（見 03 §3.2 §d、報告47 審查記錄）。

## A.5 原子標註層規範（Atomic Facts & Spans，2026-09-14 升級定案）

> **⚠️ 評測真值標準定案**：
> 1. **真值來源**：必須直接回到中華民國原始法規條文（`workspace/<kg>/<doc>/original.md`）建立，**不得以 KG Fact、B0/B1 生成答案或模型共識作為真值**。KG Fact ID 僅供下游檢索追蹤使用。
> 2. **Benchmark 資格審查（Eligibility）**：`atomic_gold_facts` 為空、標註 `[待核]`、或 `wording_status=gist` 尚未完成原文回核之題目，**一律排除於正式 Benchmark 計算**，避免未經校驗之題目污染評測數據。

### A.5.1 原子事實標註結構規格（Target Schema，⚠️ 與現行實作有落差）

每個原子事實（Atomic Gold Fact）理想上採以下結構化定義，支援確定性自動驗證：

```json
{
  "claim_id": "26-Q5-c2",
  "claim_type": "extracted",
  "target": "災後六個月期間計算起算點",
  "operator": "==",
  "value": "災害發生之當月一日",
  "critical_tokens": ["當月一日", "起算"],
  "required_spans": [
    {
      "source_doc": "N0050030_災區受災勞工保險與勞工職業災害保險及就業保險被保險人保險費支應及傷病給付辦法",
      "article": "§3",
      "start": 0,
      "end": 32,
      "exact_span": "前條所定災後六個月期間之計算，自災害發生之當月一日起計算六個月"
    }
  ],
  "forbidden_claims": [
    "自災害發生當日開始",
    "自災害發生日起算",
    "災害發生之當天"
  ],
  "mandatory": true,
  "weight": 1.0
}
```

> ⚠️ **入庫審查發現（2026-09-14）**：上述 JSON 是 **Target Schema**（理想目標），`models/eval_schema.py::AtomicGoldFact` **目前實際支援的欄位**是較精簡的子集：
> ```json
> {
>   "exact_span": "前條所定災後六個月期間之計算，自災害發生之當月一日起計算六個月",
>   "source_law": "N0050030_災區受災勞工保險與勞工職業災害保險及就業保險被保險人保險費支應及傷病給付辦法",
>   "source_article": "第3條",
>   "is_essential": true,
>   "note": "法律起算日關鍵約束，嚴禁模型平滑化改寫為當日"
> }
> ```
> 沒有 `claim_id`／`claim_type`／`target`／`operator`／`value`／`required_spans`（改用扁平的 `source_law`／`source_article`）／`forbidden_claims`／`weight`。`data/eval/test_cases.json` 目前依此精簡 schema 建立（32 題，10 題 verified）。若要達成 Target Schema 描述的完整確定性驗證能力（尤其 `forbidden_claims` 與 `critical_tokens`），`models/eval_schema.py` 需要擴充，此擴充尚未進行。

### A.5.2 標註實施四原則
1. **確定性字串切片（Exact Substring Anchor）**：`exact_span` 必須能於原文對應條文中執行 `assert exact_span in article_text` 100% 逐字命中。
2. **精度守衛與禁止斷言（Forbidden Claims）**：特別針對模型常出現的簡化與幻覺（如 26-Q5「當月一日」簡化為「當日」——⚠️ 此為前瞻性防護範例，非已證實發生的案例，見 03 §3.6 §確定性接地守衛訂正），明確列入 `forbidden_claims`，命中者直接判定不合格。**現行 `AtomicGoldFact` 尚無 `forbidden_claims` 欄位**（見 §A.5.1），此原則目前是設計目標。
3. **全鏈路血統追蹤（Lineage Tracking）**：每次測試必須記錄原始提取片段、KG 序列化與最終 Prompt 輸入，精確隔離錯誤到底發生於「檢索召回失敗」、「Fact 序列化丟棄」或「LLM 生成端扭曲」。`services/lineage_tracker.py` 已實作對應能力（見 04 §4.11），尚未接線進 `run_rq1_comparison.py` 的實際跑測迴圈。
4. **指標輸出規格**：支援下游 Scorer 自動輸出 `atomic_claim_coverage`、`precision`、`critical_token_accuracy`、`hallucination_rate` 與 `refusal_accuracy`，不再依賴人工 0/1/2 自由心證打分。`services/atomic_scorer.py::AtomicScorer` 目前輸出 `atomic_accuracy`／`atomic_recall`（見 05 §5.5.1），是這個目標的現行子集實作。
