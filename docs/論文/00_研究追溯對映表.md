## 1. 對映規則

| 標記 | 意義 |
|---|---|
| 理論／文獻 | 支撐為什麼採用某個方法、問題定義或評估方式的學術來源。 |
| 直接專案／套件 | 程式實際 import、呼叫或依賴的開源專案／套件。 |
| 架構參考 | 借鏡資料流、介面或系統概念，但本專案沒有直接使用其程式碼。 |
| 方法啟發 | 文獻或專案提供設計方向；目前實作是本專案自行設計的變體。 |
| 自有設計 | 找不到可誠實宣稱為直接來源的單一專案；應標示為本研究的工程設計，而不是硬湊參考專案。 |
| 已實作 | 有目前程式入口，且有測試或可由程式碼直接核對。 |
| 部分實作 | 有底層機制，但正式研究流程、上游接線或端到端實驗尚未完成。 |
| 設計預留 | 01–03 有研究設計或文獻依據，但目前沒有可執行的完整程式入口。 |

章節縮寫：`01` = 緒論、`02` = 文獻探討、`03` = 系統設計與方法論、`04` = 系統實作。

## 4. 「尚未實作」的精確定義

本表中的「尚未完成」不是指專案完全沒有相關程式，而是指尚未完成該研究問題所需的端到端功能與實驗閉環：

| 層級 | 判定方式 | 目前例子 |
|---|---|---|
| 基礎零件 | 已有可呼叫的函式、索引、資料欄位或限制機制 | ConceptNode KNN index、confidence、BFS hops、Fact vector search、`resolved_at` |
| 部分流程 | 零件已串接，但缺少正式研究流程、上游接線或完整查詢語意 | RQ2 ConceptNode index、RQ3 單次檢索、RQ4b entity registry |
| 完整研究功能 | 研究問題定義的演算法已接入、可跑完整資料流程，且有比較實驗與指標 | 目前 RQ2、RQ3、RQ5、RQ6 尚未達此層級 |

因此論文應使用「基礎機制已實作，但完整研究功能尚未完成」，而不要籠統寫成「完全沒有實作」。

## 6. 程式註解格式

關鍵入口採以下格式，註解只負責導航，詳細論證仍放在論文：

```python
# Traceability:
# - Thesis: 02 §2.4.x -> 03 §3.x -> 04 §4.x
# - RQ: RQx（若為工程支援而非已完成研究，明確註明）
# - Literature: 作者／年份或附錄編號
# - Project: direct dependency / architecture reference / own design
# - Tests: tests/...
```

註解中的 `Project` 若不是 direct dependency，必須使用 `architecture reference` 或 `own design`，以維持論文的可驗證性。

## 7. 最終判定

01、02、03 的主要研究問題與章節關係目前可以對齊；04 應作為「03 方法在目前專案中的實作對映章」，而不是另一篇獨立的理論章。然而「每個方法都有直接對應專案」這個命題不成立，也不應強行成立：部分方法是直接使用套件，部分是借鏡既有系統，部分是本研究自行設計。論文若照本表區分三者，研究主張會比把所有名稱列為採用專案更準確。
